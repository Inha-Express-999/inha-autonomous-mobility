2026-11-15, v0.5.11.1 / `69ef457c90a6e99cf2b243643fb260a8decdca26`, Unity 6000.3.21f1, Python 3.12.4, 관측 protocol 6. 새 Play 세션 3회에서 승객 1명, 60주년 → 비룡플라자 요청을 실제 HUD로 접수하고 정상 FIFO 배차를 사용했다. 맵·제어·안전 정책을 변경하지 않았으며 센서 무시/순간 이동은 사용하지 않았다. 개발 의존성 및 임시 관측기를 포함한 미커밋 작업 트리의 결과다.

## 결과

**3회 모두 운송 중 단절 → 정지 → 재연결 → 동일 요청 완료 → 원래 차고지 복귀/충전을 확인했다.** 각 회차의 기록 검사 14개가 통과했다. 다만 2회차에는 관측기가 실행하지 않은 추가 단절·복구가 복귀 중 기록돼, 동일한 단절 1회 조건으로 인정되는 실행은 1·3회차 2건이다. 차량도 FIFO 결과에 따라 달라지므로 고정 차량 반복 실험으로 표현하지 않는다.

차고지 도착 시간은 관측기 시작 기준이며, 최종 PASS는 그 뒤 약 2초 후 기록됐다. 정지는 속도 절댓값 0.05m/s 미만과 연결 2/3·복구 가능 상태를 함께 확인했다. 재출발은 같은 요청·차량·목적지 구간에서 새 mission, 연결 세대 2 이상, 속도 1m/s 초과를 확인했다. 최종 목표점 거리는 0.612m / 0.603m / 0.592m였다. 각 세션의 요청은 1개이며 완료 집계도 1건이다.

## 추가 단절과 측정 한계

2회차 timeline의 276.3초에 `시연 단절 · 제동 중`, 277.3초에 정지 유지, 279.4초에 연결 세대 3으로 재주행이 기록됐다. 관측기의 events.txt에는 134.8초 단절과 136.8초 복구 입력만 있다. 추가 입력의 주체/원인은 이 근거만으로 확정하지 않는다. 최종 복귀는 성공했지만 단절 1회 조건의 성능 비교에는 별도로 표시한다.

시간은 Editor wall time을 소수 1자리로 기록한 관측 지연이다. 단계 검사 주기는 최소 0.2초, 주행 timeline은 최소 1초이며 프레임 부하·화면 캡처 지연이 포함된다. 따라서 정확한 물리 제동 시간, 네트워크 지연, 안전 성능 보증으로 사용하지 않는다. 각 단절 시작 속도도 완전히 동일하지 않다.

OS 네트워크 차단, 서버 프로세스 종료/재시작, 장시간 단절, 모바일 동시 접속은 이 시험에 포함하지 않았다. 다음 단계는 서버 중단 시 Unity의 독립 정지와 재시작 후 요청 상태의 유지/유실을 구분해 검증하는 것이다.
