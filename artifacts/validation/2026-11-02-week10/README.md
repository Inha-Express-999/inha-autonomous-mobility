# 10주차 연결 장애 검증 (2026-11-02)

## PC 관제 시연
1. 통합 프로젝트의 PC 관제 화면에서 Python 서버 연결을 확인한다. 승객 요청 또는 운행 임무를 부여하고 움직이는 차량 카드를 선택한다.
2. 지도 상단에서 ‘연결 끊김 시연’을 누른다. 선택한 차량의 제어 소켓이 종료되고 제동 중 속도가 감소하는지 본다. 다른 차량 상태와 승객 요청 ID를 함께 기록한다.
3. 차량이 정지하고 ‘복구 가능’이 표시되면 ‘차량 연결 복구’를 누른다. 새 연결의 유효한 운행 명령이 오기 전까지 제동해야 한다. 운행 재개 여부는 서버가 유지한 임무와 새 명령에 따라 기록한다.
4. 화면 녹화 시 버튼 클릭, 정지, 복구 클릭, 첫 새 명령, 재출발 시점을 구분한다.

## 반복 실행
Unity Test Runner의 PlayMode에서 CampusSceneReconnectTests를 실행한다. Python 실행 파일은 CAMPUS_BRAKE_TEST_PYTHON 또는 AgentScripts/test-python.txt에 절대경로로 지정한다. 시험은 캠퍼스 씬의 V01과 전용 로컬 Python 프로세스를 사용한다.

| 시험 | 장애 부여 | 확인 범위와 복구 방법 |
|---|---|---|
| OperatorDisconnectAndRestore | 주행 중 관제 버튼과 같은 메서드를 호출 | 정지·네 바퀴 제동 후 연결 복구 호출. 새 연결에서 운행 명령 없는 차량이 정지 유지. 화면 클릭·모바일·승객 임무는 별도 검증 |
| SilentSocketBrakes | V01 전진 관측 후 Python 응답을 2초 지연 | 연결 세대가 그대로인 동안 제어 명령 만료, 제동, 정지를 확인. 지연은 자동 해제. 지연 해제 후 임무 재개는 미측정 |
| PhysicalServerRestart | 주행 중 시험 소유 Python 프로세스를 종료 | 정지 후 같은 포트에 새 서버 실행. 새 run_id를 시험 지도 객체에 반영한 뒤 V01 연결과 제동 확인. PC 지도 자동 동기화와 승객 임무 복구는 미측정 |

## 공동 검증 대기
- 실기기와 동일 승객 요청으로 PC·모바일 상태와 재접속 시간을 측정한다. 현재 단말 미정.
- 수정 씬과 기준 씬이 확정되면 동일 언덕·턱에서 LiDAR 관측을 비교한다.
- 모델링 전후 버전, 기기, 해상도, 품질, 카메라를 고정해 성능을 비교한다. 현재 버전 미정.
- legacy-restart.xml은 구형 /v1/client/ws 시험의 실패 기록이다. 현행 물리 제어 소켓 시험과 구분한다.

실행 결과: campus.xml 4/4, physical-restart.xml 1/1 통과. 구형 경로는 legacy-restart.xml 0/1. PC 버튼 시각 확인 및 실기기·승객 요청 통합은 미검증.
