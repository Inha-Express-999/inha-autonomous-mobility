## 시험 경계

- 서버 재실행은 시험 도구가 수행했다. 제품의 자동 서버 재기동 기능을 검증한 것이 아니다.
- 종료 중 state JSON은 클라이언트에 남은 이전 snapshot이다. observation_fresh나 마지막 target=18 표시를 살아 있는 서버의 최신 명령으로 해석하지 않는다. 실제 차량 속도와 제동 대기 상태를 따로 기록했다.
- 새 서버 연결 순간에는 관측이 아직 fresh가 아니었고, 15초 뒤 최종 상태에서 fresh=true를 확인했다.
- 센서 무시, 차량 순간 이동, 기존 요청 재접수, run ID 강제 교체는 하지 않았다.
- 단일 차량/경로/실행 결과이며 OS 네트워크 장애·장시간 장애·모바일 통합은 미검증이다.
- Play 종료로 재시작 서버의 소유권 정리 경로를 실행했다. 임시 Editor 도구는 Assets에서 제거하고 driver.cs.txt로 보존했다.

1. Python 권위 요청/배차/운송 단계/완료 집계/명령 중복 방지 정보를 버전 있는 저장소에 일관되게 저장한다. SQLite transaction 등 장애 중 부분 기록을 막는 방식을 검토한다.
2. 재시작 시 지도/스키마 호환성을 검사해 요청을 복원하되, 예전 연결·명령·센서·시간 만료값을 그대로 재사용하지 않는다.
3. 차량의 새 관측과 새 세션이 확보될 때까지 정지 및 배차 보류를 유지한다. 복구 가능한 요청을 같은 차량·같은 운송 단계에서 새 mission으로 재계획한다.

5. 요청 접수·탑승·운송·하차·복귀 단계별 강제 종료, 중복 완료 방지, 손상 저장소를 Python 시험으로 확인한 뒤 이번 Unity 시나리오를 재실행한다.
