# 도로 요철 보정 진행 기록

2026-10-25 · 프로젝트 0.5.0.0 이후 미커밋 작업 · **도로 재베이크·정적 형상 검증 완료**

주 도로 원본 메시는 평면이며, DSM 지형 높이를 입히는 베이크 과정에서 요철이 발생했다. 도로 외부 지형까지 평균하면 건물 기초와 주변 언덕이 도로 경사에 섞이므로 원본 도로 영역 안의 2m 격자 높이만 사용한다. 국소 평면 피팅으로 장거리 경사를 유지하며 짧은 굴곡을 줄인다. 반경 경계에서 가중치가 매끄럽게 0이 되도록 처리하고, 한 줄만 샘플링되는 좁은 도로에는 수치 정규화를 적용한다. 8m 평활화 설정은 실측 도로 제원이 아닌 개발용 가정이다.

## 현재 상태

- `RoadHeightFit.cs`: Unity 의존성이 없는 실제 베이크 계산부. 독립 .NET 실행기가 같은 소스를 링크하여 검증한다.
- `CampusRoadSmoothingValidation.BakeAndValidate`: 씬 재베이크, 삼각형 경사 감사, MeshFilter/MeshCollider 일치, 지형 관통 샘플 검사를 수행하는 Unity 배치 진입점.
- 원본 DSM·원본 도로 메시를 보존하고 생성 도로와 별도 지형 사본에 반영한다. 지형 사본은 도로 삼각형을 포함하는 격자 셀을 낮추므로 도로 옆 지형도 일부 영향을 받는다. 인접 보행로·건물 기초·허브 접합부의 시각 확인이 필요하다.
- 기존 카메라 회귀 테스트 3개 통과는 2026-10-23 결과다. 이번 계산부 수정 후의 실제 도로 주행 검증 결과는 아니다.

## 배치 검증

```powershell
dotnet run --project AgentScripts/RoadSmoothingChecks/RoadSmoothingChecks.csproj --configuration Release
```

.NET 10 SDK로 외부 패키지 없이 실행한다. 상수 높이, 비대칭 도로 경계의 평면 경사, 한 줄 샘플의 경사, 4m 파장 요철 감쇠, 샘플 경계 연속성, 샘플 없음, 반경 밖 샘플, 비정상 입력을 검사한다. 결과는 `artifacts/road_smoothing/numerical-checks.txt`에 기록한다. 합성 수치 검사이며 실제 도로 전체의 평탄성이나 주행 성공을 의미하지 않는다.

## Unity MCP 검증 결과

승인된 MCP로 정확한 프로젝트와 CampusTerrain의 미저장 변경 없음/Play 정지 상태를 확인했다. 격리 실행에서는 도구 목록이 비었고, 승인된 호스트 실행에서 연결됐다. 최종 커널로 도로 15개와 지형 사본을 재베이크했다. 최초 호출은 클라이언트의 45초 응답 대기를 넘겼지만 Unity 작업은 완료됐으며, 별도 `Validate()` 호출로 `ROAD_FINAL_VALIDATION_PASSED`를 확인했다. 응답 대기 옵션을 추가했다.

| 측정 | 최초 도로 | 최종 베이크 |
|---|---:|---:|
| 감사 대상 삼각형 | 8,697 | 4,677 |
| 수평 면적(m²) | 52,361.863 | 52,361.864 |
| 면적 가중 p95 경사 | 6.381% | 5.848% |
| 경사 10% 초과 면적(m²) | 838.896 | 595.353 |
| 최대 면 경사 | 48.729% | 46.914% |

경사는 종단/횡단을 분리하지 않은 면의 기하 경사다. 모든 도로가 수평이라는 뜻이 아니다. 중간 후보의 극소 삼각형 최대 경사 306.75% 문제는 최종 커널에서 해소됐다. `before.json`, `after.json` 및 CSV에 비교 결과를 저장했다.

`collision-audit.txt`: 도로 15개, 70,155개 샘플에서 지형 관통 0, MeshFilter/MeshCollider 참조 불일치 0, 최소 지형 이격 약 0.0494m. 전체 연속 표면에 대한 수학적 충돌 증명이나 전체 주행 성공 판정은 아니다. `road-bend.png`에 Scene View 확인 화면을 저장했다.

계산은 Editor에서만 실행하며 런타임 계산 루프를 추가하지 않는다. 도로의 기존 재질/Static Batching 플래그를 변경하지 않았고 베이크 때 bounds를 재계산한다. 삼각형 수 감소는 확인했으나 PC/모바일 FPS·메모리·배치 수 개선을 실측한 것은 아니다. 전체 경로 주행, 모든 인접 시설 접합부, 모바일 실행은 별도 검증이 필요하다.

## 짧은 물리 주행 확인

### 2026-10-25 고속 자동 경로 계측

현재 미커밋 코드와 PC_Bootstrap에서 장애물 관측을 끈 protocol 3으로 V01을 운행했다. `library-pathonly-50.csv`의 최신 실행은 15개 차로를 경유해 도서관에 도착했다. 실측 수평 이동 451.17m, 최고 50.53km/h, 4,596개 샘플이며, 마지막 상태는 목적 거점 도착이다. 순항 설정은 50km/h지만 곡선과 도착 구간은 자동 감속한다.

| 실측 속도 구간 | 차량 높이 RMS | 카메라 높이 RMS | 차량 pitch RMS | 카메라 pitch RMS |
|---|---:|---:|---:|---:|
| 30–40km/h | 2.49mm | 2.72mm | 0.331° | 0.039° |
| 40–50km/h | 2.53mm | 1.95mm | 0.351° | 0.030° |

RMS는 1초 이동 평균을 제거한 잔차이며 차량·카메라의 장거리 높이 변화를 제외한 진동 진단값이다. 전체 샘플에서 네 바퀴 동시 비접지 0회, 최대 샘플 간격 0.119초다. 변경 전 동일 경로 비교나 승차감 기준 통과를 의미하지 않는다. 원본 및 분석은 `artifacts/high_speed_drive/library-pathonly-50.csv`, `library-pathonly-50-summary.json`, `AgentScripts/analyze_drive_telemetry.py`에 있다. 모든 경로와 실제 승객 배차 상태 전이는 아직 검증하지 않았다.

이어 수행한 도서관→하이테크 25차로 경로는 **실패**했다. `hitech-50.csv`에서 약 734.71m 이동/최고 50.56km/h 후 `(Unity x=348.4, z=-65.84)` 부근에서 경로 이탈로 정지했다. 한 샘플에서 네 바퀴 동시 비접지가 기록됐고 정지 시 pitch 약 -28.6°/roll 13.9°였다. MCP WheelHit 조사에서는 네 바퀴 모두 `Campus Terrain | approximate DSM relief`에 닿았고 도로 메시 접촉이 없었다. 상공 화면 `hitech-ground-overview.png`에서 도로가 끝난 뒤 차량이 지형에 진입한 것을 확인했다. 가까운 지도 edge는 OSM way `481241714:1:0:0`이며 기존 CONNECTION_AUDIT에 적힌 확장 도로의 씬 미적용과 일치한다. `road_extensions.json`에 데이터가 있는 것만으로 활성 씬 도로 연결을 보장하지 않는다. 이 누락 도로 연결을 복구한 후 동일 경로 재검증이 필요하다. 최대 샘플 간격 1.655초로 이 실행의 프레임 공백도 별도 한계다.

### 2026-10-25 protocol 4 회차 포함 연속 주행

`hitech-turn-roundtrip.csv`: 출발점→하이테크 도착→도서관 요청→3점 회차→도서관 도착을 Unity Physics에서 연속 실행했다. 총 이동 1,491.29m, 최고 50.61km/h, 16,433개 표본, 최대 표본 간격 0.121초다. `hitech-turn-segment-summary.json`의 회차 구간은 18.08초/836개 표본/최고 2.157km/h이며 명령 부호는 전진→후진→전진이었다. 방향 전환 직전 마지막 제동 표본 속도는 각각 0.02356/0.00790km/h, 각 전환 전에 제동 표본 19개가 있었다. 네 바퀴 동시 비접지는 기록되지 않았다. CSV는 모든 제어 tick을 기록하지 않으며 방향은 명령 부호, 속도는 Rigidbody 속도 크기다.

카메라 결과에는 별도 한계가 있다. 약 125.70초에 Y가 907.13m로 전환되고 130.37초에 6.61m로 복귀한 구간이 포함된다. 이 전환이 섞인 40–50km/h 카메라 높이 RMS는 4.099m로, 주행 진동 값으로 해석하면 안 된다. 초기 카메라 전환이 아니며 당시 선택/전경 전환 원인은 기록되지 않았다. 원본과 요약은 보존한다. 차량 높이 RMS는 해당 속도 구간 7.06mm지만 카메라 흔들림 검증 완료 주장은 보류하고, 후속 계측에는 카메라 모드/블렌드 상태 기록이 필요하다. 전체 거점 검증과 실제 승객 배차 연결은 여전히 미완료다.

후속 계측 필드에 `camera_follow_requested`, `camera_blending`, `camera_live_mode`(0 미확인/1 차량 추적/2 운영 지도), `signed_speed_kmh`, `heading_deg`를 추가했다. 기존 CSV는 그대로 유지되며 해당 필드는 과거 기록에 소급해 채우지 않는다. 다음 주행에서 실제 출력 모드와 사용자 요청 모드를 비교할 수 있다.

### 하이테크 누락 도로 복구

후속 재주행 `hitech-progress-50.csv`는 **하이테크 목적 거점 도착**으로 종료했다. 실측 이동 848.80m, 최고 50.58km/h, 12,317개 표본, 네 바퀴 동시 비접지 0회다. 첫 요청은 최신 localization 미확보로 거부되어 준비 후 재요청했으며, 264.86초 계측에는 초기 정차 대기도 포함된다. 40–50km/h 구간의 1초 추세 제거 RMS는 차량 높이 7.84mm, 카메라 높이 4.94mm, 차량 pitch 0.396°, 카메라 pitch 0.026°였다. 최대 표본 간격은 0.140초다. 교차로 재방문 및 누락 도로 복구를 포함한 이 경로의 성공이며 전체 거점/실제 승객 배차/변경 전후 승차감 비교 완료를 뜻하지 않는다. 분석은 `hitech-progress-50-summary.json`에 보존했다.

2026-10-25 MCP 재연결 후 출발점→하이테크를 추가 계측했다. `hitech-steering-50.csv`는 154.91m/최고 50.53km/h 후 첫 교차로에서 `Route target behind vehicle`로 정지했다. 복구 도로에는 아직 도달하지 않았다. 이 경로는 같은 교차로를 다시 통과하며, 전체 경로에서 가장 가까운 점만 선택하면 아직 주행하지 않은 후반 경로로 진행도가 건너뛸 수 있었다. Python 제어에 직전 ego 이동 거리 기반 진행도 탐색 상한을 추가했고 재방문 교차로 회귀 검사를 포함한 주행 관련 테스트 31개가 통과했다. 회전 중 조향 곡률에 따른 속도 제한도 유지한다. 이 테스트 통과는 전체 물리 주행 성공 판정이 아니며 후속 계측으로 구분한다.

`CampusMissingRoadAuthoring`은 기존 `road_extensions.json`의 way 481241714에서 양끝이 활성 아스팔트에 닿는 미포함 구간만 추출한다. 약 65m, 합성 폭 6m의 메시·Collider를 추가했다. 원본 OSM/서버 지도/Stop 좌표는 바꾸지 않았다. 새 구간의 DSM에는 건물 부지 요철이 있어 그대로 높이 피팅하면 급경사가 생겼으므로 기존 아스팔트의 양끝 높이를 연결하는 합성 종단 경사(약 3.2%)를 별도 authoring 설정으로 저장했다. 이 구간의 DSM 표본은 주변 도로 피팅에서 제외한다.

`CampusHitechSeamAuthoring`은 양끝의 기존 보도·연석 캡을 도로 폭 안에서만 삼각형 clipping으로 제거한다. 원본 메시 에셋은 보존하고 프로젝트 전용 사본을 렌더링과 Collider에 함께 적용한다. 15cm 접속 중첩으로 비스듬한 끝의 미세 틈을 닫았다. `seam-coverage-final.json`: 두 접합부의 폭 ±2m, 종방향 ±3m에서 854개 Raycast 표본 중 아스팔트 미포함 0개. 중심 접합부 높이 차이는 약 2–4mm였으며 기존 약 12cm 연석 단차는 제거됐다.

최종 정적 검사: 도로 16개, 5,205개 삼각형, 78,075개 표본에서 지형 관통 0/메시·충돌면 불일치 0. 기존 도로의 경사 10% 초과 면적 595.353m²와 최대 면 경사 46.914%는 유지된다. 정적 검사이며 고속 주행 성공 판정과는 구분한다. 생성 메시는 Static Batching을 사용하고 공유 아스팔트 재질을 재사용한다. PC/모바일 FPS·배치 수·메모리 비용은 아직 측정하지 않았다. `hitech-ground-overview.png`는 복구 후 화면으로 갱신됐다.

CampusTerrain의 기존 Annyoung Car에 Play 모드에서만 5km/h 직진 명령을 6초, 제동을 2초 적용했다. Transform을 이동시키거나 영구 차량 설정을 변경하지 않았다. `drive-smoke.txt`: 약 8.24m 이동, 최대 속도 1.553m/s, 최대 절대 수직 속도 0.414m/s, 2,490회 Editor 관측 중 모든 바퀴가 동시에 비접지인 관측 0, 최종 속도 약 0.000017m/s. 관측은 고정 물리 tick이 아니며 변경 전 동일 주행과의 진동 비교는 수행하지 않았다. 전체 자동 경로/승객 운송 검증이 아니다. 검증 후 Play를 종료하고 임시 백그라운드 실행 값을 프로젝트 설정으로 복원했다.

Unity CLI 시도는 로그나 실행 결과가 생성되지 않아 성공으로 기록하지 않는다. 이후 사용자가 연 Unity의 MCP로 위 결과를 검증했다. 커밋/릴리스는 하지 않았으며, 커밋 시 프로젝트 버전 동기화와 새 주석 태그가 필요하다.
