# 날씨별 LiDAR와 노면 안전 정책

비·눈·안개는 합성 실험 프리셋이다. 실측 센서 성능, 타이어 마찰계수 또는 운행 안전 인증값이 아니다. 레이더와 RRT 실제 회피 주행은 추가하지 않는다.

| 날씨 | 유효 관측거리 상한 | 기본 노면 | 보수적 감속도 상한 |
|---|---:|---|---:|
| clear | 15 m (PC 설정) | dry | 2 m/s² |
| rain | 12 m | wet | 1.2 m/s² |
| snow | 8 m | snow | 0.6 m/s² |
| fog | 6 m | dry | 2 m/s² |

날씨와 노면 감속도 중 더 보수적인 값을 사용한다. wet은 1.2, snow는 0.6 m/s²이며 ice/unknown은 운행을 보류한다. 맑음·건조의 기존 반응 0.3초/여유 0.5m를 보존하고, 나머지는 0.5초/1m를 적용한다. 전체 지연을 실측한 값은 아니다.

## PC 관제 선택 (현재 작업 트리)

운행 지도 상단 바 오른쪽의 아이콘으로 **맑음 / 안개 / 비 / 눈**을 바로 선택한다. 아이콘 아래에 이름을 표시하며 파란 배경으로 현재 선택을 구분한다. 오른쪽 사이드바는 운송 요청/운행 로그 두 탭으로 구성한다.

별도 노면 선택은 표시하지 않는다. 날씨 선택 시 맑음·안개는 dry, 비는 wet, 눈은 snow를 센서와 COZY에 함께 적용한다. 현재 세션의 기존 센서와 나중에 연결되는 차량에 공통 적용하고 누락 확률·seed는 보존한다. 환경변수와 Inspector의 독립 노면 설정은 계속 사용할 수 있으며 결빙/미확인 운행 보류 정책은 유지한다. 다음 실행은 환경변수 또는 clear/dry 기본값으로 시작한다.

지도 상단에는 제목과 날씨 아이콘만 표시한다. 현재 날씨·노면·센서 적용 수 문구는 표시하지 않으며 센서·COZY·제동 정책 적용은 유지한다.

**보행자 등장** 버튼은 지도 하단 바 오른쪽에 항상 표시하며 차량을 선택했을 때만 활성화한다. 누르면 선택 차량 앞 합성 보행자가 5초간 주변을 둘러보는 Idle 모션을 재생한 뒤 횡단한다(2026-10-31 Idle 모션 보완). 차량 미선택 시 버튼은 비활성화하며 보행자 실행 결과는 Console에 기록한다. 지도 아래 안내 문구는 표시하지 않는다. 사이드바 탭 변경으로 버튼이 숨겨지지 않는다.

PC 전용 UI이며 모바일에는 추가하지 않는다. 기존 UI 재질과 0.25초 갱신 주기를 사용하고 날씨 아이콘은 작은 UI 메시로 그린다. PC·모바일 FPS/배치/메모리 성능 개선을 측정했다고 주장하지 않는다.

## 실행 설정

Unity Editor 또는 PC Player를 시작하기 **전**, 실행하는 프로세스 환경에 다음을 지정한다. 세 차량에 같은 설정이 적용된다. 이미 열린 Editor에는 환경변수가 소급 적용되지 않는다.

```powershell
$env:INHA_SIM_WEATHER = 'rain' # clear / rain / snow / fog
$env:INHA_SIM_ROAD = 'wet'     # dry / wet / snow / ice / unknown
```

노면 설정을 생략하면 표의 기본 노면을 사용한다. 잘못된 설정은 unknown 노면으로 처리해 운행을 막는다. 기본값은 clear/dry다. 시험 후 환경변수를 제거하거나 clear/dry로 설정한다.

실행 중에는 각 차량 아래 `PC Continuous LiDAR`의 `LidarSensorRig` Inspector에서 Weather, Road Condition, Scan Dropout Probability, Weather Seed를 변경할 수 있다. `ConfigureWeather`도 같은 설정을 제공한다. 누락 확률 기본값 0은 거리 제한만 적용하며, 1은 매 스캔 관측 실패 시험이다. 동일 seed와 스캔 순번은 동일한 전체 스캔 누락 패턴을 만든다. 이는 빗방울별 산란·개별 광선 오차를 재현하는 모델이 아니다. 실험 기록에는 날씨·노면·누락 확률·seed·변경 시점·코드 버전을 함께 남긴다.

## 관측과 제어

- Unity Raycast 자체의 도달거리가 줄어든다. 단순 화면 안개와 독립적이며 점군도 같은 반환을 사용한다. 360×7/10Hz는 유지한다.
- 전체 스캔 누락은 `valid=false`, `observation_complete=false`로 전송한다. 빈 점군으로 안전을 주장하지 않는다. 포화/지연/통신 단절의 기존 정지 경로를 유지한다.
- Python은 서버의 날씨별 거리 상한도 적용한다. 차체 앞뒤 길이를 제외한 확인 가능 거리 안에 `v*t + v²/(2*a) + margin`이 들어가도록 속도를 제한하고, 현재 속도로 불가능하면 먼저 제동한다. 기존 도로/곡률/18km/h 상한은 함께 적용한다.
- 관측 실패·장애물 위험·결빙/미확인 노면은 정지·대기한다. 회복 후 5개 연속 정상 clear scan을 요구한다. 날씨·노면·관측거리 변경도 연속 확인을 다시 시작한다.
- 객체 Transform·실제 상대속도·미래 궤적은 새로 전송하지 않는다.

## 호환성과 한계

물리 protocol 5의 LiDAR에 선택 필드 `weather`, `road_condition`, `observation_complete`를 추가했다. 새 서버는 과거 관측을 clear/dry/complete로 해석한다. 구 서버는 추가 필드를 거부하므로 **서버와 Unity 클라이언트를 함께 갱신**해야 한다. 지도 schema 및 독립 transport gateway 계약은 변경하지 않는다.

노면 설정은 Python의 제동 계획 가정이다. Unity WheelCollider 마찰곡선·노면 재질·눈 적설·침수·광학 산란·객체 추적을 추가하지 않았다. 따라서 눈길에서 해당 감속도를 실제로 달성한다거나 악천후 안전 주행을 검증했다는 뜻은 아니다. 실제 Physics 제동거리 측정과 미끄러짐 모델은 후속 검증이다.

## COZY 고정 날씨 (2026-10-29 · 0.5.6.0)

CampusTerrain의 COZY Weather 3.6.23에 날씨 토글을 연결했다. 프로젝트 전용 `Resources/CampusWeather`의 Clear/Rain/Snow/Fog 프로필을 사용하고, 기존 COZY 원본 에셋은 수정하지 않는다. 비/눈은 각각 Light Rain/Light Snow 입자 효과, 안개는 Dense Fog 효과를 사용한다.

관제 선택 시 COZY weather ecosystem을 manual 모드로 두고 선택 프로필 하나의 가중치를 1로 유지한다. 예보 목록과 이전 블렌드 관계를 분리하고, 매 COZY weather 계산 전에 선택을 유지하므로 무작위/예보/시간 경과가 날씨를 바꾸지 않는다. 시간 모듈과 카메라 설정은 유지한다. 현재 UI는 날씨에 기본 노면을 연결하며 기존 LiDAR 감속/정지 정책을 그대로 따른다. 화면에는 COZY 연결/고정 상태를 함께 표시한다. PC 환경 선택이 시작된 뒤 Additive로 늦게 불러온 COZY도 바인딩한다.

COZY 연출의 안개 농도/눈 입자가 Raycast 물리 광학 모델을 대신하지 않는다. 센서 성능 저하는 기존 합성 거리/누락 모델이 담당한다. Light Rain/Light Snow 프리셋을 사용했지만 PC·모바일의 FPS/배치/메모리 성능 개선을 실측한 것은 아니다.

COZY 고정 전환과 기존 UI 통합 5개 시험은 통과했다. 추가 실제 씬 재로딩 시험에서는 에디터에 보이던 COZY가 씬 파일에는 없어 실패했다. 다시 추가한 사용자 객체를 현재 설정 그대로 씬에 명시적으로 저장했고, 이후 씬을 다시 열지 않고 YAML의 객체/스크립트 포함 여부를 확인했다. 이 재로딩 시험은 제거했으며, 검증 실행기는 COZY가 에디터에만 있고 파일에는 없으면 PlayMode 시험을 거부한다. 자동으로 사용자 씬을 저장하거나 다시 만들지 않는다. 원본 XML과 저장 확인은 `artifacts/validation/2026-10-29-cozy-weather`에 보존한다. 실제 캠퍼스 날씨별 운송 및 모바일/Player 시험은 미실행이다.

## 하단 바·속도·대기열 UI (2026-10-29 · 현재 작업 트리)

배차 방식(FIFO/Greedy)·경로 탐색(A*/Dijkstra)은 지도 하단 바 왼쪽에 배치한다. 기존 HTTP 정책 변경 경로를 사용한다. 차량 추적 화면 왼쪽 아래에는 선택한 차량의 Rigidbody 속력(m/s × 3.6)을 정수 km/h로 표시하며 지도 복귀/선택 해제 시 숨긴다. 물리 바디가 없으면 속력을 추정하지 않고 —로 표시한다.

오른쪽 요청 대기열은 이전 배차/경로 카드 영역까지 확장한다. 서버 `SharedState.queue` 순서대로 요청 ID와 출발/목적 랜드마크를 표시하고 긴 목록은 스크롤한다. 빈 목록/서버 연결 대기를 구분하며 연결 해제 시 이전 요청을 숨긴다. 합성 대기열을 런타임에 만들지 않는다.

`PcEnvironmentRegressionRunner.Run()` PlayMode 5/5 통과. 하단 배치·환경 문구 제거·차량 미선택 시 버튼 비활성·선택 시 활성·5 m/s→18.0 km/h 표시·선택 해제 시 속도 숨김·요청 순서/경로 표시와 연결 해제 시 초기화를 확인했다. 3840×2160 독립 UI 캡처로 배치를 확인했다. 캡처의 R101/R102와 속도 입력은 시험 fixture이며 실제 운송 측정이 아니다. 실제 캠퍼스 운송·보행자 물리 횡단·모바일·Player 빌드 및 성능은 이번 변경에서 재검증하지 않았다.
