## A*와 노드 시연

웹 기본 탐색은 A*이며, 요청/가용 차량 배차는 기존 FIFO를 유지한다. 선택한 탐색은 픽업·운송·자기 거점 복귀의 세 구간에 적용된다. 서비스 라이브러리 기본 Dijkstra 기준선은 유지한다. 탐색 선택 변경은 이후 배차부터 적용하며 이미 배차된 경로를 교체하지 않는다. 초기화는 선택한 탐색을 유지한다.

1. 지도 위 **노드 보기**를 누르면 기존 그래프의 187개 노드를 표시한다. 다시 누르면 숨긴다. 균일 격자를 새로 깐 것이 아니라 OSM/Unity 도로 중심선에서 보존한 노드다. graph에는 402개 방향 간선이 있으며 배경의 흰 보행/주변 도로 전체가 운행 그래프인 것은 아니다.
2. 출발/도착을 선택하고 **선택 구간 비교**를 누른다. A*가 실제 확장한 노드를 주황색으로, 경로를 파랑으로 표시한다. Dijkstra와 동일 graph/cost snapshot에서 비용·확장 노드 수·길이·실행 시간을 비교한다. 이 미리보기는 배차/요청을 만들지 않는다.
3. **경로 탐색**에서 A*/Dijkstra를 선택하고 요청 또는 기존 시나리오를 접수한다. FIFO, 차량 3대, 30km/h, 배터리/충전은 유지한다.

자체 A*는 `h(n)=직선거리(n,목표)*min(edge_cost/edge_chord)`를 사용한다. 모든 간선에서 일관적인 하한이며 비용 snapshot에 0비용이나 임의 비용이 있어도 과대추정하지 않는다. 폭/계단/폐쇄/통행 제약과 geometry 복원은 Dijkstra와 같은 코드를 사용한다. 비용 동일 시 선택 경로/거리나 배터리는 달라질 수 있으며 알고리즘이 최단 시간에서 동률인 경우 하나를 결정적으로 고른다. 실측 실행 시간은 실행마다 달라지고 노드 수 감소가 항상 더 빠른 실행을 뜻하지 않는다.

## 배차 선택과 성능 비교

기본 FIFO 기준선을 보존하고 관제의 **배차**에서 Greedy/Hungarian을 선택할 수 있다. 이후 배차에 적용하고 기존 임무는 유지한다. 별도 `/demo/comparison.html`의 **배차 비교**는 같은 요청/초기 차량/배터리를 별도 인스턴스에서 재실행한다. 혼합 12건, 기존 5개 목적지/18건 충전, 현재 접수 기록과 1/3/5회 반복, 조건 해시/요청별 배정/JSON 저장을 제공한다. 자세한 비용·우선순위·부분 매칭·지표 정의와 한계는 [배차 비교 안내](DISPATCH_COMPARISON.md)를 따른다. 기본 시나리오의 동시 요청은 batch로 접수한다. 전체 backend 187개 검증을 통과했다. 사용자 제공 PNG를 세 화면의 브랜드 및 탭 아이콘으로 포함했다.

## RRT / TTC 보조 탭

상단 **RRT / TTC**는 `/demo/avoidance.html`로 이동한다. 합성 센서 입력을 Python 알고리즘에 보내 RRT 트리/정적 우회 후보, 장애물 팽창, 1/2초 상대운동과 충돌 TTC, 정지거리를 SVG로 표시한다. 정적/횡단 선택, 위치/속도 조정, 오래된 관측과 트리 표시를 제공한다. 노후 관측은 STOP·빈 경로, 횡단 객체는 TTC 판단과 동적 RRT 보류를 표시한다.

이 API는 배차 세션을 생성/진행시키지 않는다. Unity 센서 수신이나 캠퍼스 운행의 장애물 회피로 표현하지 않는다. 탭을 오가도 서버 운행은 기존 일시정지/배속 상태로 계속된다. 모든 RRT 후보는 executable=false이며 [세부 범위](LOCAL_AVOIDANCE.md)를 따른다.

검증: backend 147개 통과, Ruff/format check와 두 JS 구문 검사 통과. 임의 그래프 10개 총 2,250 OD는 Floyd–Warshall과 비교했고, 캠퍼스 Stop 196 OD에서 A*/Dijkstra 비용 일치와 확장 노드를 비교했다. 브라우저 1600px/390px에서 노드/탐색 비교·보조 탭을 확인했다. 시간 성능의 p95 목표 달성 보고는 아니다.

재현: `python scripts/validate_global_planning.py`는 196 OD 비교와 FIFO 5건 완료/충전 결과를 `artifacts/global_planning_validation.json`에 저장한다. 이번 실행의 총 확장 노드는 A* 8,788개 / Dijkstra 17,752개였으며 이 값은 현 지도/비용에 한정한다.

## 화면 조작

- **이동 요청:** 출발·도착 거점, 승객/물품, 인원/중량을 선택하고 접수한다. 출발=도착은 거부한다. 대기 요청을 취소할 수 있다.
- **지도:** 드래그/휠 또는 확대·축소 버튼으로 이동한다. 키보드 방향키와 +/-도 지원한다. 전체 보기로 원래 범위를 복원한다.
- **거점 클릭:** 출발/도착 선택 상자를 먼저 선택한 뒤 지도 거점을 클릭한다. 이후 클릭 대상은 출발/도착을 번갈아 선택한다. 거점은 검증된 승하차장이 아닌 도로 투영 후보다.
- **복귀 후 충전:** 즉시 수행할 대기 요청이 없으면 잔량 100% 미만인 차량이 자동 충전한다. 잔량 30% 미만까지 기다리지 않는다. 충전은 가상 시간이 진행되어야 증가하므로 일시정지 중이면 시작 버튼을 누른다. 완충 후 FIFO에 재진입한다. 새 요청이 들어오면 충전 중에도 왕복 에너지와 15% 예비량을 확보한 차량은 후보가 되며, 선택된 차량만 충전을 중단한다. 부족하면 필요한 잔량 도달 시 재평가한다. 대기 요청을 바로 수행할 수 있으면 배차를 우선한다.
- **차량 카드:** 선택 차량의 경로만 강조한다. 다시 클릭하면 전체 차량 경로를 표시한다. 실선/점선으로 운송/복귀 경로를 구분한다.
- **재생:** 초기에는 정지 상태다. 시작/일시정지와 1·5·10·30·100·300배속을 선택할 수 있다. 배속은 서버 시계에 적용되므로 배차·복귀·충전도 같은 시간으로 진행한다.
- **초기화:** 확인 창을 거쳐 웹 시연의 시간·요청·차량·배터리만 초기화한다. 기존 `/v1/requests` 메모리 서비스는 유지한다.

같은 서버에 접속한 브라우저 탭들은 하나의 웹 시연 세션과 제어를 공유한다. 새로고침은 시연 상태를 지우지 않는다. 서버를 재시작하면 메모리 상태는 사라진다. 여러 독립 시연이 필요하면 포트를 달리한 서버를 실행한다. 인증/사용자별 시연 격리는 구현하지 않았으므로 localhost 시연용으로 사용한다.

## 2026-10-19 팀 시연 순서

1. **지도 소개:** 원본 도로/건물, 운행 그래프, 14개 거점 후보와 차량 3대를 설명한다. OSM 출처 표시를 유지한다.
2. **FIFO:** 초기화 후 「캠퍼스 5개 목적지」를 누른다. 5건을 접수하고 10배속으로 자동 시작한다. V01·V02·V03 배정과 나머지 2건 대기를 보여준다.
3. **왕복:** 일시정지하고 차량 카드를 선택한다. 목적지 도착 후에도 차량은 복귀 중이며, 자기 거점으로 돌아와야 다음 요청을 받는 모습을 설명한다. 역은 Unity 자료에 대응하는 우회 복귀 경로를 쓴다.
4. **충전:** 초기화 후 「배터리·충전 시나리오」를 누른다. 하이테크 요청 18건이 추가되고 100배속으로 시작한다. 분산 거점으로 이동거리가 달라져 이전 정문 집중 배치의 충전 횟수·시각과 다르다. 300배속으로 바꿔 복귀·충전·재배차를 빠르게 보여준다.
5. **확장 계획:** 현재는 경로 시간 재생이며, 다음에 Unity 차량/Physics·센서·도착 판정을 연결한다고 설명한다.

시나리오 버튼은 기존 요청에 추가한다. 정해진 대기 건수/충전 순서를 보여주려면 먼저 초기화한다. 지도 자료·의존성이 모두 로컬에 있으므로 행사장 인터넷이 없어도 실행할 수 있다. 발표 전 페이지를 열어 정상 표시와 포트 충돌 여부를 확인한다.


`웹 입력 → 시연 API → 기존 MobilityService → FIFO/Dijkstra/배터리 → 상태 응답 → SVG 표시` 순서다. 브라우저는 경로 탐색이나 배차를 대신 계산하지 않는다. 서버 상태를 200ms마다 조회하고 화면 사이에는 최대 350ms 범위에서 서버가 보낸 간선별 경로·시간을 재생한다. 직선으로 목적지에 연결하지 않는다. 스냅샷 사이의 표시는 예측이며 Physics 위치가 아니다. 차량이 같은 위치에 겹치면 배지를 벌리고 실제 위치로 연결선을 그려 구분한다. 실제 좌표는 바꾸지 않는다.

디자인은 루트 `UI_DESIGN_SYSTEM.md`, `PC_CLIENT_DESIGN.md`를 웹에 적용한다. Primary #1677FF·네이비 제목·흰 카드·2px 아웃라인 SVG·차량 ID/색상·충전 상태 배지를 함께 사용한다. 구현하지 않은 센서/혼잡/보행자 항목을 수치나 가짜 메뉴로 표시하지 않는다. Freesentation 400/500/600/700 웹폰트를 `backend/src/campus_sim/web/fonts/`에 포함해 본문, 입력, 버튼, SVG 지도 글자에 적용한다. 외부 CDN 없이 제공하며 원본 SIL OFL 1.1 라이선스와 출처/해시는 같은 폴더에 보존한다. 설명 문구와 중간점 표시는 줄이고 거점 이름과 도로 경로는 유지한다.

## 범위와 한계

OSM 기반 2D 형상 표시와 후보 경로 시연이며 통행·폭·승하차·보행 접근성 승인이 아니다. 건물은 캐시 OSM의 닫힌 building way이며 relation/실제 외관/전체 시설 커버리지를 보장하지 않는다. 도로 선 굵기는 보기 위한 스타일이며 실제 도로 폭이 아니다. 배터리는 2,000Wh·0.35Wh/m·주행 보조전력 50W·세 거점별 독립 충전 1포트/1,000W·예비량 15%·대기 전원 OFF의 합성 가정이다. Unity 통신/물리/센서·충돌 회피·실제 교통/혼잡·실제 배터리/충전소는 구현하거나 검증하지 않았다.

상단 Inha Mobil 로고(아이콘과 이름 전체)는 `/demo/`로 이동하는 일반 링크이며 메인에서도 클릭하면 문서를 다시 불러온다. 서버의 시연 요청/차량 상태를 초기화하지 않는다. 사용자 제공 브랜드/파비콘은 캐시 구분 파일 `inha-mobil-logo-579cbb6f.png`를 사용한다.

### 2026-10-19 UI 최종 정리

상단은 캠퍼스 관제 / RRT·TTC 두 메뉴다. `polish.css`에서 공통 헤더·탭·입력·카드·상태 배지를 통일하고 Freesentation을 유지한다. 배차/경로와 재생/시간/배속/초기화는 데스크톱에서 한 줄이며 중복 알고리즘 안내 문구를 제거했다. 관제 1600×900·1280×720, 실험 1280×720의 한 화면 배치와 390px 관제의 가로 넘침 없음을 브라우저에서 확인했다. 작은 화면은 세로로 배치하며 세부 정보는 펼쳐보기·대화상자로 연다. 실험 슬라이더/체크박스는 일반 입력창의 최소 높이를 상속하지 않는다.
