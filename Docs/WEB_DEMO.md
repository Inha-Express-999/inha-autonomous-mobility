# OSM 웹 2D 시연

프로젝트 0.2.3.0 · 2026-10-18 · 로컬 Python 가상 시간 운행

이 화면은 기존 Python FIFO·Dijkstra·배터리 모델을 사용한다. Unity Physics/센서 주행을 구현한 화면이 아니다. 외부 지도 타일·CDN·지도 API 키·인터넷 연결 없이, 저장소의 확장 OSM 건물/도로 형상과 기존 운행 그래프를 SVG로 표시한다.

## 실행

현재 개발 PC에서는 저장소 루트에서 다음을 실행한다.

```powershell
.\scripts\start_web_demo.ps1
```

브라우저에서 **http://127.0.0.1:8765/demo/** 를 연다. 터미널을 켜 두고, 종료할 때 Ctrl+C를 누른다. 포트를 사용 중이면 `-Port 8766`으로 실행한다. 스크립트는 로컬 가상환경 또는 현재 Python을 사용하고, 이 개발 PC의 임시 의존성 폴더가 있으면 함께 읽는다. 지도 묶음을 재생성해 줄바꿈·원본/설정 hash 차이를 해소한다. 실행 중 파일을 바꾸거나 여러 서버가 같은 파일을 재생성하지 않도록 한다.

새 PC에서는 Python 3.11 이상 환경을 준비한다. 이번 실제 검증은 Windows/Python 3.14.4다.

```powershell
python -m pip install -r backend/requirements-dev.lock
python -m pip install --no-deps -e .\backend
python -m campus_sim.map_builder
campus-sim serve
```

지도 원본과 데이터가 포함된 저장소에서 실행해야 한다. wheel만 별도 복사하면 OSM 원본이 없어 실행할 수 없다. 지도 누락/해시 오류는 원인을 수정하고 재생성하며, 가짜 지도로 대체하지 않는다. PowerShell 스크립트를 실행할 수 없는 환경에서도 위 Python 명령을 직접 실행할 수 있다.

## 화면 조작

- **이동 요청:** 출발·도착 거점, 승객/물품, 인원/중량을 선택하고 접수한다. 출발=도착은 거부한다. 대기 요청을 취소할 수 있다.
- **지도:** 드래그/휠 또는 확대·축소 버튼으로 이동한다. 키보드 방향키와 +/-도 지원한다. 전체 보기로 원래 범위를 복원한다.
- **거점 클릭:** 출발/도착 선택 상자를 먼저 선택한 뒤 지도 거점을 클릭한다. 이후 클릭 대상은 출발/도착을 번갈아 선택한다. 거점은 검증된 승하차장이 아닌 도로 투영 후보다.
- **차량 카드:** 선택 차량의 경로만 강조한다. 다시 클릭하면 전체 차량 경로를 표시한다. 실선/점선으로 운송/복귀 경로를 구분한다.
- **재생:** 초기에는 정지 상태다. 시작/일시정지와 1·5·10·30·100·300배속을 선택할 수 있다. 배속은 서버 시계에 적용되므로 배차·복귀·충전도 같은 시간으로 진행한다.
- **초기화:** 확인 창을 거쳐 웹 시연의 시간·요청·차량·배터리만 초기화한다. 기존 `/v1/requests` 메모리 서비스는 유지한다.

같은 서버에 접속한 브라우저 탭들은 하나의 웹 시연 세션과 제어를 공유한다. 새로고침은 시연 상태를 지우지 않는다. 서버를 재시작하면 메모리 상태는 사라진다. 여러 독립 시연이 필요하면 포트를 달리한 서버를 실행한다. 인증/사용자별 시연 격리는 구현하지 않았으므로 localhost 시연용으로 사용한다.

## 2026-10-19 팀 시연 순서

1. **지도 소개:** 원본 도로/건물, 운행 그래프, 14개 거점 후보와 차량 3대를 설명한다. OSM 출처 표시를 유지한다.
2. **FIFO:** 초기화 후 「캠퍼스 5개 목적지」를 누른다. 5건을 접수하고 10배속으로 자동 시작한다. V01·V02·V03 배정과 나머지 2건 대기를 보여준다.
3. **왕복:** 일시정지하고 차량 카드를 선택한다. 목적지 도착 후에도 차량은 복귀 중이며, 정문에 돌아와야 다음 요청을 받는 모습을 설명한다. 역은 Unity 자료에 대응하는 우회 복귀 경로를 쓴다.
4. **충전:** 초기화 후 「배터리·충전 시나리오」를 누른다. 하이테크 요청 18건이 추가되고 100배속으로 시작한다. 300배속으로 바꾸면 마지막 충전 완료까지 약 37초의 실제 시간이 필요하다. 100배속이면 약 111초다. 실행 지연을 제외한 이론적 배속 시간이다.
5. **확장 계획:** 현재는 경로 시간 재생이며, 다음에 Unity 차량/Physics·센서·도착 판정을 연결한다고 설명한다.

시나리오 버튼은 기존 요청에 추가한다. 정해진 대기 건수/충전 순서를 보여주려면 먼저 초기화한다. 지도 자료·의존성이 모두 로컬에 있으므로 행사장 인터넷이 없어도 실행할 수 있다. 발표 전 페이지를 열어 정상 표시와 포트 충돌 여부를 확인한다.

## 파일 구조와 데이터 흐름

```text
backend/src/campus_sim/
├─ web_demo.py          독립 세션, 배속 시계, 원본 OSM 표시, 경로상의 위치
├─ web/
│  ├─ index.html        한국어 관제 화면
│  ├─ style.css         공통 디자인 토큰·반응형 화면
│  ├─ icons.svg         2px 아웃라인 SVG 아이콘
│  └─ app.js            요청·제어, 상태 폴링, SVG 지도·차량 재생
├─ api.py               /demo/ 정적 파일과 /v1/demo/* API
└─ 기존 service/planning/dispatch/battery 모듈
scripts/start_web_demo.ps1
```

`웹 입력 → 시연 API → 기존 MobilityService → FIFO/Dijkstra/배터리 → 상태 응답 → SVG 표시` 순서다. 브라우저는 경로 탐색이나 배차를 대신 계산하지 않는다. 서버 상태를 200ms마다 조회하고 화면 사이에는 최대 350ms 범위에서 서버가 보낸 간선별 경로·시간을 재생한다. 직선으로 목적지에 연결하지 않는다. 스냅샷 사이의 표시는 예측이며 Physics 위치가 아니다. 차량이 같은 위치에 겹치면 배지를 벌리고 실제 위치로 연결선을 그려 구분한다. 실제 좌표는 바꾸지 않는다.

디자인은 루트 `UI_DESIGN_SYSTEM.md`, `PC_CLIENT_DESIGN.md`를 웹에 적용한다. Primary #1677FF·네이비 제목·흰 카드·2px 아웃라인 SVG·차량 ID/색상·충전 상태 배지를 함께 사용한다. 구현하지 않은 센서/혼잡/보행자 항목을 수치나 가짜 메뉴로 표시하지 않는다. Pretendard가 설치되어 있으면 우선 사용하고, 없으면 시스템 한글 폰트를 사용한다.

## API와 검증

- GET `/v1/demo/map`, GET `/v1/demo/state`
- POST `/v1/demo/requests`, POST `/v1/demo/requests/{id}/cancel`
- POST `/v1/demo/control` — `{"speed":100,"paused":false}`
- POST `/v1/demo/scenario` — `{"name":"extensions"}` 또는 `{"name":"battery"}`
- POST `/v1/demo/reset`

전체 pytest 99개, Ruff 검사/포맷, JavaScript 구문 검사를 수행한다. 추가 8개 테스트는 배속/정지, 간선별 위치, 역 복귀, 5건 FIFO, 18건/6회 충전, 초기화, OSM 원본 표시, HTTP·세션 분리를 다룬다. 브라우저에서는 실제 시나리오 클릭·차량 3대·대기열·경로·정지·충전·화면 크기를 확인한다. 별도 검증 기록은 `artifacts/web_demo_validation.json`이다.

## 범위와 한계

OSM 기반 2D 형상 표시와 후보 경로 시연이며 통행·폭·승하차·보행 접근성 승인이 아니다. 건물은 캐시 OSM의 닫힌 building way이며 relation/실제 외관/전체 시설 커버리지를 보장하지 않는다. 도로 선 굵기는 보기 위한 스타일이며 실제 도로 폭이 아니다. 배터리는 2,000Wh·0.35Wh/m·주행 보조전력 50W·정문 독립 충전 3포트/1,000W·예비량 15%·대기 전원 OFF의 합성 가정이다. Unity 통신/물리/센서·충돌 회피·실제 교통/혼잡·실제 배터리/충전소는 구현하거나 검증하지 않았다.
