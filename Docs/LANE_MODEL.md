# 차로 모델 · 0.5.0.0

기존 CampusTerrain과 원본 도로/차선 에셋을 유지한다. maps/inha_osm_runtime/lane_profiles.json은 정적 지도 hash와 원본 Unity 도로 JSON의 개행 독립 source hash를 고정한 별도 schema_version=1 프로필이다. 원본 그래프 402개 방향 edge 중 폭 출처가 있는 400개를 분류했다. 출처가 없는 2개는 차로 운행에서 제외한다.

도로 폭은 Unity 제작에 사용한 합성 폭이며 현장 측정/유효 차도 폭/통행 허가가 아니다. 현재 V01 도로는 campus.json의 7m 가정 폭을 사용한다. 양방향이며 폭 5.5m 이상이면 한 방향당 한 차로로 가정해 lane_width=road_width/2, 우측 중심 offset=road_width/4를 적용한다. 이 구간은 차로 폭 3.5m, offset 1.75m다. 더 좁은 양방향 구간은 중심 공유 차로로 구분하며 실제 교행 가능 판정이 아니다. 단방향 구간은 가운데 단일 차로를 사용한다.

A*는 도로 연결을 유지하면서 차체 반폭+0.2m 여유가 들어가는 차로만 후보로 둔다. 시작점은 현재 실제 위치에서 정방향 차로에 투영한 접근 경로다. 차량을 이동/회전시키지 않는다. 반대 방향 edge는 반대편 우측 차로를 사용한다. 노드의 차로 끝을 단순히 직선으로 이어 붙이지 않고 차량 wheelbase/최대 조향각으로 얻은 최소 회전 반경을 고려해 cubic 교차로 곡선을 만든다. 여유 길이가 없거나 U-turn이면 전진 자동 운행을 거부한다.

실행 중 route cross-track과 최소 차로 폭, 자기 Collider에서 측정한 반폭, 0.2m 개발 여유로 허용 횡오차를 계산한다. 이를 벗어나면 OFF_ROUTE 제동한다. 전방 Raycast 제동/0.4m 해제 hysteresis/watchdog은 유지한다. 이 여유와 lookahead/속도는 실측 안전 한계가 아닌 초기 시뮬레이션 설정이다.

물리 protocol 2는 half_width_m 측정값을 요구한다. 기존 protocol 1은 중심선 Baseline과 동일 계약을 지원하며 연결 중 protocol 변경은 거부한다. 차로 프로필 hash와 lane ID/폭/횡오차는 같은 웹 세션 상태에 기록한다. 정적 지도 schema_version/map_version 및 geometry hash는 바꾸지 않는다.

교차로 곡선은 경로 기하를 연결하는 단계다. 보행자 우선권·신호·다중 차량 예약/CBS·실제 도로 접근성 승인과 전체 승객 상태 전이를 완료한 것으로 보고하지 않는다. 단일 실제 차량 V01을 사용하고 V02/V03은 기존 가상 시연 차량이다.

0.5.0.0에서는 차로 운행 직선 최대 18km/h, 곡률 미리보기 감속과 동적 lookahead를 사용한다. 원본 그래프의 제한속도보다 빠르게 명령하지 않는다. 센서 hit를 ego 좌표로 받아 계획 차로의 통과 영역과 비교하며 옆 차로의 검출만으로 불필요하게 제동하지 않는다. 관측 누락 시 보수적인 기존 전체 ray 최솟값을 유지한다. 장애물 제동 시작 시 해제 거리를 고정해 감속 후 재출발 반복을 방지한다. 사용자 요청으로 차량별 운행 중지 UI/API는 제거했으며 카메라 추적 해제와 차량 자동 안전 제동은 별개다.
