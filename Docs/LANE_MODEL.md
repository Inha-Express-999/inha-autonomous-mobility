## 2026-10-25 미커밋 경로 범위 점검

후속 protocol 4 회차 연결: `all-stop-turn-route-audit.json`은 동일 예상 도착 pose에서 134/183개 경로 생성(기존 protocol 3의 111개 대비 23개 추가)을 기록한다. 제1생활관의 출발점 도달 문제와 나머지 경로는 여전히 미해결이다. `physical_turn.py`는 직선 도로의 연속 구간과 최소 폭을 확인하고, 회차 종료 후 경로도 생성되는 경우에만 회차를 선택한다. `TurnController`는 실제 후륜 위치를 기준으로 2km/h 미만에서 추종하고 각 방향 전환점에서 3회 연속 정지 관측을 요구한다. 실제 차체가 도로 범위를 벗어나거나 추종 오차가 0.3m를 넘으면 OFF_ROUTE로 정지한다. 이는 개발용 수치이며 실제 차량 안전 기준이 아니다. Python 관련 검증 55개 통과, 실제 Unity 회차는 검증 중이다.

`AgentScripts/audit_physical_routes.py`는 실제 mission 경로 생성기를 사용해 기존 V01 시작점과 각 경로의 예상 도착 위치·방향에서 다음 거점 경로를 검사한다. 도착 위치는 경로 끝점과 접선으로 계산한 값이며 실측 Unity 도착 pose가 아니다. `artifacts/high_speed_drive/all-stop-route-audit.json`에 지도/차로 hash와 조합별 결과를 저장했다.

현재 시작점→거점 14개 중 13개, 예상 도착 pose를 포함한 전체 183개 조합 중 111개가 생성됐다. 제1생활관은 시작점에서 경로가 생성되지 않아 그 거점 출발 13개는 검사하지 못했다. 하이테크·인하대역·제2생활관 예상 도착 pose는 다른 거점으로 출발하는 13개 경로 모두 실패했다. 제3생활관·정문은 각각 1개만 성공했다. 도착 가능과 후속 배차 가능을 구분해야 하며, 전진 회전 연결/도착 방향과 출발 접합부를 보완하기 전에는 전체 거점 물리 배차 완료로 보고할 수 없다.

이 결과는 경로 생성 검사다. 도로 Collider 일치, 고속 실제 주행, 승객 요청 상태 전이, 다중 차량 조정의 통과를 의미하지 않는다. 기존 시간 기반 가상 배차는 별도이며 Unity 소유 차량은 여전히 그 가상 배차 후보에서 제외된다.

## 기존 기준선

### 막다른 도로 회차 준비(미연결)

MCP 실측 `artifacts/high_speed_drive/turnaround-measure.json`: V01 BoxCollider 범위 X ±0.46001m, Z ±0.9m, 후륜 축 Z=-0.65m, 축거 1.299996m, 최대 조향 0.5235988rad. 따라서 후륜 중심 기준 보수적 반길이는 1.55m다. 이 값으로 폭 6m/전방 여유 5m/후방 여유 3m의 **합성 직선 공간**에 대한 회차 기하 검사도 통과했다. 공간 치수는 특정 거점의 실측 여유가 아니며, 전체 차로 감사는 실측 반폭 0.46001m로 재실행했다. 회차 단위 검사 총 11개가 통과했다.

하이테크 도착 후 재출발을 추적한 결과, 가까운 정방향 edge는 지도 clip 끝으로 향하며 끝의 유일한 출구는 반대 방향 edge다. 현재 `lane_path`는 이 U-turn을 거부한다. 정방향 차로 폭 검사를 풀거나 좌표를 이동시키는 수정으로 해결할 문제가 아니다.

`backend/src/campus_sim/turnaround.py`에 직선 도로 안의 전진/후진/전진 3개 원호 회차 기하를 추가했다. 후륜 축 중심을 기준으로 하며, 호출자가 전달하는 전체 차체의 보수적 반폭/반길이와 도로 앞뒤 여유를 검사한다. 표본 사이 차체 이동 상한도 여유 폭에 포함한다. 각 방향 전환점은 정지 후 다음 구간을 실행해야 한다. 공간 부족/미지원 차로 간격/잘못된 입력은 거부한다. 후진 명령 계약·회차 상태기계·실측 차체 치수 전달·Unity 실제 회차는 아직 연결하지 않았으며 경로 생성 성공 수는 기존 111/183에서 증가한 것으로 보고하지 않는다. 합성 치수를 사용한 기하 검사 10개와 기존 주행 관련 검사를 합해 41개가 통과했다.

기존 CampusTerrain과 원본 도로/차선 에셋을 유지한다. maps/inha_osm_runtime/lane_profiles.json은 정적 지도 hash와 원본 Unity 도로 JSON의 개행 독립 source hash를 고정한 별도 schema_version=1 프로필이다. 원본 그래프 402개 방향 edge 중 폭 출처가 있는 400개를 분류했다. 출처가 없는 2개는 차로 운행에서 제외한다.

도로 폭은 Unity 제작에 사용한 합성 폭이며 현장 측정/유효 차도 폭/통행 허가가 아니다. 현재 V01 도로는 campus.json의 7m 가정 폭을 사용한다. 양방향이며 폭 5.5m 이상이면 한 방향당 한 차로로 가정해 lane_width=road_width/2, 우측 중심 offset=road_width/4를 적용한다. 이 구간은 차로 폭 3.5m, offset 1.75m다. 더 좁은 양방향 구간은 중심 공유 차로로 구분하며 실제 교행 가능 판정이 아니다. 단방향 구간은 가운데 단일 차로를 사용한다.

A*는 도로 연결을 유지하면서 차체 반폭+0.2m 여유가 들어가는 차로만 후보로 둔다. 시작점은 현재 실제 위치에서 정방향 차로에 투영한 접근 경로다. 차량을 이동/회전시키지 않는다. 반대 방향 edge는 반대편 우측 차로를 사용한다. 노드의 차로 끝을 단순히 직선으로 이어 붙이지 않고 차량 wheelbase/최대 조향각으로 얻은 최소 회전 반경을 고려해 cubic 교차로 곡선을 만든다. 여유 길이가 없거나 U-turn이면 전진 자동 운행을 거부한다.

실행 중 route cross-track과 최소 차로 폭, 자기 Collider에서 측정한 반폭, 0.2m 개발 여유로 허용 횡오차를 계산한다. 이를 벗어나면 OFF_ROUTE 제동한다. 전방 Raycast 제동/0.4m 해제 hysteresis/watchdog은 유지한다. 이 여유와 lookahead/속도는 실측 안전 한계가 아닌 초기 시뮬레이션 설정이다.

물리 protocol 2는 half_width_m 측정값을 요구한다. 기존 protocol 1은 중심선 Baseline과 동일 계약을 지원하며 연결 중 protocol 변경은 거부한다. 차로 프로필 hash와 lane ID/폭/횡오차는 같은 웹 세션 상태에 기록한다. 정적 지도 schema_version/map_version 및 geometry hash는 바꾸지 않는다.

교차로 곡선은 경로 기하를 연결하는 단계다. 보행자 우선권·신호·다중 차량 예약/CBS·실제 도로 접근성 승인과 전체 승객 상태 전이를 완료한 것으로 보고하지 않는다. 단일 실제 차량 V01을 사용하고 V02/V03은 기존 가상 시연 차량이다.

0.5.0.0에서는 차로 운행 직선 최대 18km/h, 곡률 미리보기 감속과 동적 lookahead를 사용한다. 원본 그래프의 제한속도보다 빠르게 명령하지 않는다. 센서 hit를 ego 좌표로 받아 계획 차로의 통과 영역과 비교하며 옆 차로의 검출만으로 불필요하게 제동하지 않는다. 관측 누락 시 보수적인 기존 전체 ray 최솟값을 유지한다. 장애물 제동 시작 시 해제 거리를 고정해 감속 후 재출발 반복을 방지한다. 사용자 요청으로 차량별 운행 중지 UI/API는 제거했으며 카메라 추적 해제와 차량 자동 안전 제동은 별개다.
