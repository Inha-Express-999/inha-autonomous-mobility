# 구현 현황

프로젝트 버전 **0.2.3.0** · 2026-09-25 작업본. 이 문서는 현재 checkout을 기준으로 하며, 과거 검증 기록과 현재 단계 판정을 구분한다. 근거가 없는 기능은 완료로 표시하지 않는다.

## 클라이언트·Python 기반의 한계

- Python `backend/`는 서비스 기반이다. 현재 합성 ETA는 그래프 경로 길이와 edge 허용속도에 기초한 값이며, 실제 위치·혼잡·승하차 시간의 현장 측정 ETA가 아니다. 합성 서버 요청 성공은 실제 시뮬레이션 운송 성공이 아니다.
- Unity fixture는 합성 snapshot이다. 0.1.5.0 시점 fixture 화면 검증과 0.1.6.0 서버 기반은 같은 네트워크 실행이 아니다.
- PC에는 합성 환경에서 승객/화물 입력 및 운영자 취소 UI가 추가됐다. Landmark 검색, 지도 위 차량/경로 그리기, 공통 JSON Schema 파일, 이벤트 delta, Unity Physics/센서 연동은 미완료다. Mobile은 합성 Landmark 순환 선택, step-free 선택 및 승객 create/cancel command UI가 있다. 서버 차량·경로 좌표는 합성 graph 좌표이며 일반 Unity 캠퍼스 씬 차량을 움직이지 않는다. Python HTTP/ASGI는 검증했지만 새 PC UI의 Unity 실행·전송 왕복, 씬 수명주기, 세션/부하 안정성은 미검증이다. 검증 범위와 위험은 [서버 안정성 메모](server_stability.md)에 기록한다.
- 2026-09-24 검증용 임시 Python 3.12.14 virtual environment에 프로젝트 `backend[dev]`를 설치해 `python -m pytest backend/tests -q -p no:cacheprovider`를 실행했다: **34 passed, 1 warning**. 포함 범위는 서비스·경로/요청 상태·benchmark·HTTP·ASGI WebSocket 통합 및 lifespan clock 진행이다. 남은 경고는 Starlette에서 httpx TestClient 사용 deprecation이다. Ruff는 `ruff check backend/src backend/tests AgentScripts/UnityWebSocketSmoke/drop_first_ack_app.py`에서 통과했다. 런타임/테스트 패키지 버전은 임시 환경의 FastAPI 0.141.1, Starlette 1.7.0, Pydantic 2.13.5, httpx 0.28.1, pytest 8.4.2, Ruff 0.16.8이며 저장소에 lockfile로 고정되지 않았다. 별도 Mono smoke 도구로 C# source의 실 WebSocket 통합을 검증했으나 Unity Player/EditMode/PlayMode suite 및 실기기는 검증되지 않았다. Unity MCP `RunCommand`에서 합성 6-node/6-Stop/12-edge loader smoke가 통과한 과거 기록은 유지한다.

## M1 RoadGraph·경로 탐색 초안

**현재 검증 갱신(2026-09-25):** Python backend 61개와 `AgentScripts/MapData` 9개 테스트(총 70개), Ruff가 통과했다. WebSocket 통합 테스트가 ego 위치 보고→PC 요청→pickup/dropoff service→`COMPLETED` 흐름과 목적지 route polyline을 검증하고, pickup 경로와 dropoff 재계획에 서로 다른 route ID가 발행되는지 확인한다. PC 전용 `sensor_observation` 입력 계약은 현재 신선한 ego pose tick에 연결하고 polar/local 좌표 일치, 센서별 중복 tick, 최대 detection 수와 LIDAR/RADAR 상대 속도 규칙을 확인해 latest frame을 메모리에 둔다. Unity source에는 64-beam 2D RaycastNonAlloc 생성기와 pose ACK 이후 최신 sensor frame을 보내는 adapter가 추가됐다. 차량/보행자 physics layer를 선언하고 spawner가 차량 collider hierarchy에 Vehicle을 적용한다. C# DTO edge-case self-test와 loopback Python 서버 smoke에서 constructed sensor frame ACK를 확인했다. Unity 6000.3.21f1 Bee response-file의 asmdef별 참조를 사용한 현재 Domain·Networking·Presentation·Mobile·PC C# 소스 및 EditMode/PlayMode test assemblies standalone compile이 오류/컴파일러 경고 없이 통과했다(analyzer/source-generator 제외). Unity Editor import·Test Runner compile/run 결과로 간주하지 않는다. Unity Physics hit·pedestrian 분류·Editor/Player 왕복은 아직 검증되지 않았다. 이 입력은 인지 정확도나 안전 판단을 증명하지 않는다. OSM review validator는 공식 접근 근거·현장 측정 근거와 원본 금지 태그 충돌 검사를 추가했다. `/health`는 프로젝트/schema/map 버전, 지도 상태·그래프 규모를 확인하는 합성 fixture 진단이다. Unity Editor Test Runner·Play Mode와 실제 지도는 이 검증에 포함되지 않는다.

- 입력 계약/검증: `backend/src/campus_sim/road_graph.py`. graph는 현재 `schema_version=1`, 독립 `map_version`, `data_status`, 좌표 프레임, 출처 날짜/hash/원점, 노드/Stop, 방향 edge의 전체 geometry·길이·폭·허용 차량 클래스·속도·zone·출처·검증 상태·비용 penalty·서비스 허용과 step-free 조건을 기록한다. 미지원 필드/스키마 버전, 중복 ID, 없는 endpoint, endpoint와 geometry 불일치, geometry보다 짧은 edge 길이, 비유한 값은 거부한다.
- fixture: `maps/fixtures/campus-synthetic-6.json`. 6개 합성 Stop·랜드마크와 양방향 edge 12개를 포함한다. 폭 4m 등 graph 숫자는 알고리즘용 합성 가정이며 실측값이 아니다. 좌표·연결은 캠퍼스 실제 위치가 아니며 운송 가능한 지도 데이터가 아니다. schema_version 1과 map_version `synthetic-campus-6stop-v1`은 프로젝트 버전과 독립이다. 서비스의 synthetic V01은 요청당 passenger group 또는 cargo 한 건을 처리하도록 설정했으며 passenger capacity 4, wheelchair slots 1, cargo capacity 20kg도 fixture 가정이다. 이 수치는 차량 모델의 실측 제원이 아니다.
- planner: `backend/src/campus_sim/planning.py`에 자체 Dijkstra/A*를 구현했다. edge 비용은 `length_m / allowed_speed_mps + crowd_penalty_s + zone_penalty_s + expected_wait_s`; 폐쇄, 서비스/차량 클래스 부적합, 입력된 차량 폭보다 좁은 edge, 요구 step-free 미충족 edge는 Hard Constraint로 탐색에서 제외한다. A* 휴리스틱은 직선거리/그래프의 최대 허용 속도다.
- 실행: `PYTHONPATH=backend/src python -m campus_sim.cli route-compare --map maps/fixtures/campus-synthetic-6.json`. `--start-stop`·`--goal-stop`을 같이 주면 한 OD, 생략하면 모든 ordered distinct OD를 비교한다. `--pair-count`, `--warmups`, `--repetitions`로 정렬된 OD의 표본 수·워밍업·반복 측정을 고정하고, 출력에 경로/비용/길이, expanded nodes, 고유 generated nodes, peak open set, 계약 검증 건수, elapsed_ns 표본의 mean/min/p50/p95/max를 기록한다. 2026-09-24 실제 CLI 재검증은 `maps/fixtures/campus-synthetic-benchmark-11.json`에 `--repetitions 20 --warmups 2`를 적용했다. 전체 110 ordered OD, 110/110 동일 경로 비용, 20/20 반복 일치, 알고리즘별 2,200 timing sample이 나왔다. 한 합성 실행에서 A* 확장량이 더 적었던 OD는 97/110이었다. 시간 수치는 장비·실행 상태 의존 진단값이며 캠퍼스 성능 또는 일반 우월성 증거가 아니다.
- 실행 결과(합성 fixture, 단일 실행): 전체 OD 비용 일치 30/30, 도달 가능 30/30, A* expanded nodes가 더 적은 pair 11개, 평균 expanded nodes Dijkstra 3.0/A* 2.53. step-free 제약에서도 비용 일치 30/30, A* expanded nodes 우세 3쌍, 평균 Dijkstra 3.0/A* 2.9. Stop 1→4 경로 비용은 양 알고리즘 모두 102초, 경로는 stop 1→2→5→6→4다.
- T03 benchmark fixture: `maps/fixtures/campus-synthetic-benchmark-11.json`. 11개 가상 노드로부터 lexicographic ordered-pair 앞 100개를 고정하고, 34 directed edge와 102 polyline 점을 포함한다. 모든 geometry·길이·연결·속도 값은 알고리즘 검증용 합성 가정이며 인하대 캠퍼스 경로를 나타내지 않는다.
- T03 실행 확인(2026-09-24, 로컬 Python 호환 harness): `campus_sim.cli.main()`과 실제 planning/evaluation 코드를 사용해 100개 OD × 20회, 알고리즘별 2,000개 elapsed_ns 표본을 실행했다. warmup 2회 뒤 모든 반복에서 경로 결과가 일치했고 Dijkstra/A* Path Cost는 100/100 일치, A*가 더 적은 노드를 확장한 pair는 89/100이었다. 로컬 한 번의 p50/p95는 Dijkstra 16,700/25,800ns, A* 10,800/23,100ns였다. 이는 합성 그래프와 이 실행 환경의 진단 결과이며 알고리즘 일반 우위나 목표 성능 증거가 아니다.
- 검증 제한: 호환 harness는 현재 bundled Python에 Pydantic/pytest가 없어 RoadGraphDocument loader를 실행하지 못해 fixture topology/geometry를 harness에서 별도 검사했다. `evaluation.py`, `cli.py`, 테스트 파일은 `py_compile`을 통과했지만 `pytest backend/tests/test_evaluation.py`는 `No module named pytest`로 실행하지 못했다. 따라서 표준 Python 환경의 Pydantic 계약 검증과 pytest 결과를 확인하고 T03 결과를 정식 기록하는 작업은 남아 있다.

## 차량 모델·프리팹 준비 상태

최근 커밋 `f97fa11`에서 원본 차량 모델과 시각 프리팹을 추가했다. Unity Editor 6000.3.21f1 확인에서 세 원본 프리팹에는 Transform/MeshFilter/MeshRenderer만 있고 Collider/Rigidbody가 없었다. 이번 변경으로 `Assets/CampusSim/Prefabs/Vehicles/VehicleActor_Annyoung.prefab`, `VehicleActor_Default.prefab`, `VehicleActor_Induck.prefab` wrapper를 생성했다. wrapper는 unit scale root, 원본 nested visual prefab, 측정한 Renderer AABB의 BoxCollider, gravity off·kinematic Rigidbody를 가진다. Unity Editor component/property 조회에서 구성과 bounds를 검증했다. 이는 시각 에셋과 재사용 가능한 물리 껍데기이며 동역학·차량 제원·축/접지·안전 제동·주행 controller 검증이 아니다. 측정값 및 재생성 방법은 [차량 에셋 준비 상태](vehicle_asset_readiness.md)에 기록했다.

주행 그래프 노드·edge는 지도 데이터 계약을 원본으로 삼고, graph node/Stop marker·edge 시각화 요소는 `Prefabs/Navigation/` 아래 prefab으로 제공한다. `RoadGraphVisualizationLoader`는 현 schema-v1 synthetic fixture만 가져올 수 있으며 실제 지도 importer는 없다. 장면 GameObject Transform을 주행 graph 원본으로 쓰지 않는다. 캠퍼스 반복 환경물은 구조가 안정적이고 여러 위치/씬에서 공유되는 항목부터 프로젝트 소유 prefab/variant로 정리한다. 상세 기준은 [AGENTS.md](../AGENTS.md)의 지도 그래프·캠퍼스 오브젝트 재사용 규칙을 따른다.

## Python–Unity WebSocket 초기 연결

- 서버 경로 `ws://<host>:8765/v1/client/ws`. 첫 메시지는 `type=subscribe`, `schemaVersion=3`, 네 자리 `projectVersion`, `role`이며 Mobile은 `subscriberId`도 보낸다. schema와 프로젝트 버전은 독립이며 schema 불일치만 거부한다.
- 서버는 `connected`와 목표 10Hz(0.1초 간격) `snapshot` envelope를 보낸다. snapshot은 기존 C# `WorldSnapshotDto` schema v3용 camelCase JSON이다. Unity는 백그라운드 수신 후 `Pump`에서 Unity 메인 스레드의 `WorldStateStore`에 적용한다. 10Hz는 fake socket cadence 테스트로 확인했으며 외부 네트워크에서의 cadence/performance 실측은 아니다.
- Unity Bootstrap의 `useFixture`를 끄면 WebSocket을 사용한다. 기본 주소는 `ws://127.0.0.1:8765/v1/client/ws`; 모바일 기기에서는 PC 서버의 LAN 주소로 설정한다.
- 현재 연결은 합성 alpha다. Mobile passenger의 `create_request`·`cancel_request` command와 `command_ack` 이후 요청이 다음 주기 snapshot에 반영된다. 같은 메모리 서비스가 합성 6-stop graph를 읽어 V01의 A* 경로를 만든다. route snapshot은 polyline segment별 합성 목표속도를 제공하고 PC follower는 이를 로컬 최대속도와 함께 적용한다. Mono C# WebSocket smoke에서 실제 snapshot의 속도 배열 길이와 양수값을 검증했으며 PlayMode 속도 추종 테스트는 추가했지만 아직 실행하지 않았다. 서버 합성 ETA/이동은 5m/s 상한과 정적·시간대 edge 지연 비용을 반영하며, 픽업/하차 서비스 각 2초 뒤 상태가 진행된다. PC 전용 `ego_localization`은 map/vehicle/session/tick/pose·속도 검사 후 최신 값을 저장하고 ACK를 주지만, Unity Physics에서 값을 수집하지 않고 synthetic runtime 위치도 바꾸지 않는다. 위치·속도·서비스 시간은 합성 데모값이지 실측값이나 실제 차량 제어가 아니다. `subscriberId`는 인증이 아니므로 신뢰 네트워크에만 서버를 공개한다.
- 2026-09-25 최신 Python backend 89개+MapData 9개 pytest(합계 98개)와 Ruff 검사가 통과했다. PC-only sensor role rejection 통합 테스트는 10Hz snapshot이 ACK보다 먼저 도착할 수 있는 순서를 허용하도록 수정했으며, 같은 테스트를 8회 연속 실행해 통과를 확인했다. HTTP/ASGI WebSocket handshake/timeout/message limit/schema rejection, FastAPI lifespan clock, localization runtime/snapshot/arrival/stale transition을 포함한다. [Mono smoke harness](../AgentScripts/UnityWebSocketSmoke/README.md)는 현재 저장소의 C# client/domain source를 빌드해 PC·Mobile 동시 WebSocket 연결, snapshot, PC localization 및 constructed sensor-frame ACK, PC passenger/cargo create/cancel, 첫 passenger ACK 유실 후 동일 message ID 재전송/요청 중복 방지를 검증했다. Sensor DTO의 polar/local mismatch, LIDAR relative speed, 65개 detection edge-case와 PC/Mobile snapshot의 route segment speed profile 역직렬화·polyline 길이 일치 smoke self-test도 통과했다. 별도 Unity Bee response-file compile에서 Domain/Networking/Presentation/PC 및 EditMode/PlayMode test assemblies가 현재 source로 컴파일됐다. Unity Test Runner에서 PlayMode 실행과 실제 Player 주행은 아직 검증하지 않았다. 서버 측 0.1초 snapshot cadence 별도 측정은 fake socket 테스트 범위다. Harness는 Unity Player가 아니므로 Unity SynchronizationContext·씬/UI·실기기는 검증하지 않는다. 외부 네트워크 부하 및 동시 연결 부하는 포함하지 않는다. 검증 조건과 위험은 [서버 안정성 메모](server_stability.md)에 기록했다.
