# 합성 에너지 모델과 배차 제한

2026-09-26 · v0.4.1.0 체크포인트

## 실행과 가정

```text
campus-sim serve --energy-config configs/energy.synthetic.json
```

기본 서버에서는 꺼져 있고 명시적 설정으로 켠다. 설정은 합성 6-stop map version, graph node에 대응하는 충전 거점 n1/n6, 차량별 초기 잔량, 모델 용량·주행 Wh/m·보조전력 W·승객/화물 보정과 출처를 고정한다. 샘플 수치는 실험용 가정이며 실제 배터리·충전 시설·차량 소비량을 확인한 값이 아니다. 앱 초기화에서 지도·충전 node·활성 차량 범위를 검사하고 기존 모델의 무단 덮어쓰기를 거부한다. `/health`는 `SYNTHETIC_MODEL` 또는 `DISABLED`를 표시한다.

소모 모델은 `거리×Wh/m×적재 보정 + 보조전력×시간/3600`이다. Wh/m은 보조전력을 제외한 주행분으로 정의하고 보조전력은 이동·서비스·대기 중 계속 차감한다. 승객/화물 보정 계수와 최대 속도는 명시적인 합성 가정이다. 모델 수치는 실측 SOC가 아니다.

## 배차·운송 연결

Greedy/Hungarian이 공유하는 후보 생성에서 차량→pickup, loaded pickup→dropoff, unloaded dropoff→도달 가능한 충전 node, 승하차 서비스 에너지와 용량의 **15% 이상 예비량**을 확인한다. 지도 geometry의 전체 polyline 길이, 경로 속도·비용 가산 및 알려진 Python 제어 속도 상한을 사용한다. 충전소별 현재 planner 경로 중 에너지 요구량이 작은 것을 선택한다. 전체 에너지 최적 경로 탐색은 아니다.

잔량 부족, 충전 경로 없음, 미지정 차량/지도 불일치/에너지 구간 오류는 후보 제외다. 큰 비용을 부여해 강제로 할당하지 않는다. 동일 서비스를 두 번 수행할 때 초기 용량으로 돌아가지 않고 소비 후 잔량을 사용한다. 배차 비교 snapshot도 에너지 실패를 별도 사유와 required_wh/charger_node로 남길 수 있다. 에너지의 초 단위 비용 환산 및 희소 차량 순위 패널티는 아직 없다.

합성 stepper는 통과한 polyline segment마다 이동량을 차감하고, 승차 전/후 요청 상태로 적재 보정을 적용한다. Unity 모드에서는 승인된 연속 ego 위치 표본 간 XY 거리를 차감한다. 같은 tick의 재전송은 재차감하지 않는다. 세션 변경이나 선언 속도 범위를 넘는 위치 변화는 잔량을 신뢰할 수 없는 상태로 만든다. Unity 표본 사이의 실제 곡선 거리와 누락된 이동은 정확히 복원하지 못하므로 이 값은 추정이며 전력 실측 검증이 필요하다.

수행 중에는 남은 현재 route, 아직 시작하지 않은 운송 구간, 충전 복귀와 예비량을 재평가한다. 부족하거나 충전 경로가 사라지면 요청·route·위치를 보존하고 정지/지원 필요 상태로 둔다. 현재 계약의 `EMERGENCY_STOP + VEHICLE_FAILURE`를 사용하며 센서 정지 사유가 우선한다. Unity 실제 측정 속도를 0으로 덮어쓰지 않는다. 합성 stepper는 위치 진행을 멈춘다. 불확실한 요청 ETA는 null이다.

`batteryWh`는 기존 nullable 필드에 모델 잔량을 제공하며, 오류·미설정에서는 null이다. PC 문구는 '배터리 추정'으로 표시한다. 새 통신 enum이나 schema version은 추가하지 않았다. 에너지 전용 안내 사유와 화면/단말 확인은 남아 있다.

## 확인한 동작

- 4m 빈 차 이동 + 4m 적재 이동 + 8m 충전 복귀, 적재 보정 1.5, 0.1Wh/s 보조전력과 15Wh 예비량의 합성 사례에서 필요량 35Wh.
- 35Wh는 배정 가능하고 34.999Wh는 제외한다. 비교의 1e-9Wh 허용치는 부동소수점 누적 오차용이다.
- 12초 운송 후 실제 합성 경로/시간 차감 결과 23.8Wh이며, 다음 운송은 부족해 대기한다. 이는 충전 이동을 실행한 결과가 아니다.
- 두 배차 알고리즘의 실제 다중 차량 batch에서 저잔량 차량을 제외한다.
- 운송 중 잔량 부족/충전 경로 폐쇄는 위치·요청 보존, 센서 정지 우선, 현재 세션 중복 pose 차감 방지, 곡선 stepper 길이와 제어 속도 상한을 검사한다.

전체 Python/MapData 455개 통과 후 알려진 controller 속도 상한 반영과 배터리 표시 유효성 검사를 보완하고 에너지 검사 22개가 통과했다. Ruff·diff 검사 통과. 실행별 소스/로그는 `artifacts/validation/2026-09-26-energy-admission/`에 있다. 이번 단계에서는 Unity를 재실행하지 않았다.

## 남은 범위

자동 충전소 이동·충전 대기열·충전 시간/점유·충전 완료, staging hub 재배치, 실제 제원·배터리 센서, 에너지 고장 복구, Physics 주행 왕복 및 전체 부하 검증은 미완료다. 오래 대기하거나 모델 가정보다 소비가 커지면 지원 정지하며, 자동으로 잔량을 복원하거나 충전소로 순간이동하지 않는다. 차량 안전 제동 성능이나 실제 캠퍼스 운행 가능성을 인증하지 않는다. 전체 MVP 및 M5 완료가 아니다.
