# 허브 차고 및 실제 차량 배차 · 미커밋 작업

2026-10-26, 프로젝트 버전 0.5.0.0 기준의 미커밋 작업이다.

## 초기 배치와 복귀

V01 정문, V02 후문, V03 운동장 옆 주차장에 간단한 개방형 차고를 둔다. 기존 허브 도로 노드와 차로 프로필에서 출발 위치·방향을 계산하며 도로를 임의로 연결하지 않는다. 차고는 기존 도로 위의 시뮬레이션용 통과형 보관 공간으로, 실제 시설 위치·통행 허가를 의미하지 않는다. 양쪽 출입구가 열려 있어 어느 합법적인 도착 방향으로도 내부에 정차할 수 있다. 차량은 초기 씬에서만 배치되며 운송 도중 위치를 강제 복원하지 않는다.

`AgentScripts/prepare_home_garages.py`는 측정된 동일 차량 프리팹 치수와 서버 지도에서 `Assets/CampusSim/Data/home_garages.json`을 생성한다. `CampusGarageAuthoring.Build`는 지도 hash 및 세 출발점과 차고 중심의 실제 도로 Collider를 검사한 다음 씬 배치를 저장한다. V02/V03은 V01과 동일한 WheelCollider 차량 구성을 복제하고 명시적인 차량 ID로 서버에 각각 연결한다. 기존 가상 운행 차량과 동일 ID의 실제 Physics 소유권이 생기면 가상 운행에서 제외된다.

기존 정류장이 없는 V03 허브도 복귀할 수 있도록 `home:<vehicle_id>` 목적지를 지원한다. 명령 차량 자신의 기존 `home_nodes`만 허용하고 다른 차량의 차고 ID나 임의 좌표는 거부한다. 승객용 정류장 데이터나 정적 지도 hash는 변경하지 않는다.

## FIFO / Greedy

Unity PC 패널의 FIFO/Greedy 드롭다운은 웹과 동일한 `/v1/demo/control`의 `dispatch`를 변경한다. `physical_dispatch`도 실제 선택한 정책을 반환한다. 진행 중인 운송은 유지하며 이후 배차에 적용한다. 기존 웹 Hungarian도 동일 실행기에서 지원하되 Unity의 선택지는 요청 범위인 두 방식이다.

FIFO는 요청 생성 순서와 실제 가용 차량의 대기 순서를 따른다. Greedy는 기존 구현의 우선순위·장기 대기 보호·결정적 동률 규칙을 재사용하고, 실제 ego에서 계획한 픽업/운송/복귀의 가능성, 적재·접근성, 왕복 배터리를 먼저 확인한다. 비용은 픽업 시간 + 0.5×운송 시간 + 2×지각 + 에너지 충전 환산 시간 + 이동지원 차량 희소성이다. 경로 거리/순항속도와 회차 거리/저속으로 계산한 비용이며 실측 ETA가 아니다.

여러 차량의 왕복 경로를 동기 계산하면 0.4초 localization 유효 시간을 넘길 수 있어 후보 한 개씩 스케줄러 tick에 나눠 평가한다. 비용·가능성만 캐시하고, 위치/방향/차체 치수가 바뀌면 다시 계산한다. 배터리는 배차 직전 재검사한다. 실제 출발은 최신 ego로 경로를 새로 만들며 관측 유효 시간을 완화하지 않는다.

## 웹 공통 배터리 모델

실제 물리 차량도 `configs/osm_runtime.json`의 공통 배터리 정책을 사용한다. 현재 합성값은 2,000Wh, 거리당 0.35Wh/m, 운행 보조전력 50W, 예비량 15%, 충전 20,000W다. 2026-10-27 사용자 요청으로 기존 1,000W에서 이상적인 고속 충전으로 변경했다. 순 저장 전력을 일정하게 적용해 0→100%는 6분, 15→100%는 5분 6초이며 충전 후반 감속·온도 제한은 모델링하지 않는다. 실제 차량 제원이나 충전 시설의 성능을 뜻하지 않는다. 설정은 서버 시작 시 로드하므로 기존 서버에는 재시작 후 반영된다. 승객/화물 적재 보정은 운송 구간에만 적용한다. 운송 요청뿐 아니라 직접 지정한 실제 주행에도 관측된 이동 거리로 에너지를 차감한다. 대기 차량은 웹 설정과 같이 전원을 끈 모델로 유휴 소모를 계산하지 않는다.

자기 허브 노드 4m 이내에서 정차하고 실제 위치 관측이 유효할 때만 충전한다. 차고 외형의 수납 범위에 맞춘 시뮬레이션 판정이며 실제 충전 접촉 센서는 아니다. 같은 tick을 여러 번 처리해도 중복 충전하지 않고 연결 단절/일시정지 시간을 소급 충전하지 않는다. 왕복+예비량이 확보되면 충전 중인 차량도 배차 후보가 되며 선택된 차량만 충전을 중단한다. 충전 세션과 SOC는 기존 웹 응답에 통합하고 Unity 차량 카드에도 잔량·충전·복귀 상태를 표시한다. 이는 모델 에너지이며 실측 배터리 SOC가 아니다.

## 렌더링과 검증 범위

차고는 공용 Cube 메시와 프로젝트 전용 재질, Static Batching 플래그를 사용한다. 도로면과 휠 접촉을 바꾸지 않도록 차고 장식에는 Collider를 두지 않는다. 월드 간판은 깊이 검사를 적용한다. 차량 2대 추가의 프레임 시간·배치 수·메모리는 아직 측정하지 않았으며 모바일 성능 개선 완료로 표현하지 않는다.

코너 검증 프로필의 횡가속도 제한은 2.4→3.6m/s²로 조정했다. 동일 곡률의 제한 속도는 약 22% 증가하며 표준 프로필, 차로 이탈, 관측 신선도, 조향·도착 감속 제한은 유지한다. 실제 차량 성능값이나 승차감 합격 기준이 아니다.

Python 관련 주행·웹·배차·배터리 회귀 158개 통과(Starlette TestClient 의존성 deprecation 경고 1개). 실제 세 차량 시작 위치의 도로 Collider와 `PARKED`/fresh 연결을 확인했다. 실제 Greedy는 후문 V02를 선택했고 픽업/회차/하차 후 도로를 침범한 하이테크 외벽을 보정하자 같은 복귀 임무를 이어 차고 도착·예약 해제·충전까지 완료했다. 약 60.39초 동안 16.67Wh 증가했다. 진단 정지가 포함된 실행이므로 전체 운송 시간 비교로 사용하지 않는다. 사전 출발 경로 생성은 각 차량 13/14개이며 제1생활관과 전체 거점 왕복, 다중 차량 충돌 조정은 미완료다. 최신 실제 운송 결과는 `implementation_status.md`와 `artifacts/high_speed_drive/`를 따른다.
