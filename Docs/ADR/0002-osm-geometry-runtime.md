# ADR 0002: OSM/Unity 형상 기반 시간 실행과 검증 지도 모드 분리

상태: 채택 · 2026-10-15 · 프로젝트 0.2.2.0

사용자는 기존 OSM과 Unity 자료를 사용해 차량 1대의 FIFO·Dijkstra 왕복 시간 계산을 연결하도록 요청했다. 저장소에는 원본 형상이 있으나 운송용 폭·통행·Stop·보행 접근성 승인은 없다.

## 결정

- 기본 서버/데모를 `maps/inha_osm_runtime/`로 전환한다. 기존 가상 6거점은 명시적 `--synthetic` 회귀 모드로 보존한다.
- OSM node ID를 연결 기준으로 사용하고 Unity campus.json 범위의 차량 도로 중심선을 적용한다. 가까운 점/교차선/출입구를 임의의 차량 edge로 연결하지 않는다. 보행로와 알려진 제한, 미지원 조건/회전 제한은 제외한다.
- Unity 일반 출입구 후보를 기존 도로 선분에 투영해 Stop 후보를 둔다. 35m는 실험 설정이며 보행 거리/접근성 승인이 아니다. step-free는 미검증이므로 허용하지 않는다.
- `osm_geometry_simulation`은 실제 형상과 합성 운행 가정을 구분한다. `synthetic_geometry=false`, `operationally_verified=false`를 반환한다. 기존 RoadGraph.synthetic는 미검증 가정 허용 플래그로 true이며 검증 지도 모드의 unknown 제외 규칙은 변경하지 않는다.
- 계산 좌표는 WGS84/AEQD다. Unity 기존 grid와 명시적으로 변환하며 2차원 수평 길이를 사용한다. 속도 30km/h(약 8.33m/s)와 차량 용량은 가정이다. 배터리는 제외한다.
- 기본 V01은 정문 도로 Stop 후보로 복귀한다. 픽업/운송/복귀를 각각 탐색하고 기존 가상 타이머로 요청 완료/차량 복귀/재배차를 분리한다. 원본/생성 코드/산출물 해시가 맞지 않으면 실패한다.

## 결과와 한계

형상 기반 시간 실행은 연결했지만 M1/M2 전체 검증 완료는 아니다. 14개 Landmark 중 후보 10개/정문 왕복 가능 9개다. 하이테크는 왕복 불가로 대기하며 생활관 1·2·3/인하대역은 후보가 없어 요청을 거부한다. 실제 도착·정지·승하차·안전은 Unity/센서 통합에서 검증해야 한다. 실제 운송 모드에서는 별도 검증 overlay와 폭·제원·보행 접근 승인이 필요하다.
