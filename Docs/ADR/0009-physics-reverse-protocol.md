# ADR 0009 — 저속 회차를 위한 Physics protocol 4

상태: 회차 제어 연결 및 하이테크 실제 회차 검증 · 2026-10-25 · 미커밋

후속 구현: `physical_turn.py`와 `TurnController`를 protocol 4의 경로 생성/관측 제어에 연결했다. 전진 경로가 없을 때만 정렬된 직선 도로 띠에서 회차 공간을 검사하고, 예상 회차 종료 pose로 후속 경로가 생성되는 것을 확인한 뒤 회차를 선택한다. 예상 pose는 계획에만 사용하고 실제 ego를 덮어쓰지 않는다. 각 방향 전환점은 정지 관측 3회를 요구한다. 55개 관련 테스트 통과. 오프라인 거점 조합은 134/183개 생성되며 실제 Unity 회차는 별도 검증 중이다. 아래 미연결 설명은 계약 추가 당시 상태다.

## 문제

일부 Stop 후보는 막다른 도로에 연결된다. 전진만 가능한 기존 경로는 도착 후 재출발을 거부한다. 순간 회전/좌표 이동 대신 전진·후진·전진 회차를 추가하려면 후진 명령과 후륜 기준 차체 길이가 필요하다.

## 결정

- Physics 관측/명령의 독립 schema_version=4를 추가한다. 프로젝트 VERSION·지도 hash·다른 API schema는 바꾸지 않는다.
- 관측에 `rear_axle_offset_m`(기존 ego 기준, 전방 양수)과 `half_length_m`(후륜 중심에서 전체 차체를 포함하는 보수적 반길이)을 요구한다. Unity의 자기 BoxCollider/WheelCollider에서 측정하며 다른 객체 Ground Truth는 전달하지 않는다.
- 명령의 음수 속도는 protocol 4의 `MANEUVER` 상태에서만 허용하고 하한은 -5km/h다. 구버전의 음수 명령은 거부한다. 전진 순항 상한은 50km/h이며 실제 회차에는 별도의 낮은 목표 속도와 완전 정지 후 방향 전환이 필요하다.
- Unity는 protocol 4로 연결하고 응답 버전·속도·상태·유효기간을 검사한다. 기존 watchdog/접지/ego freshness 제약은 유지한다. 연결 도중 버전 변경은 여전히 금지한다.
- 기존 서버의 protocol 1~3 지원을 유지한다. 새 Unity 클라이언트는 protocol 4 지원 서버가 필요하다. 버전 불일치에서는 운행하지 않으며 로컬 서버를 새 코드로 재시작해야 한다.

## 구현과 한계

`turnaround.py`는 회차 기하만 생성한다. protocol 4는 이 기하를 실행하기 위한 통신 준비다. 아직 서버에서 음수 제어 명령을 생성하지 않으며, 거점별 공간 검증·회차 추종·방향 전환 정지 상태기계·배차 연결·Unity 실제 회차는 후속 구현 대상이다. 이 변경만으로 111/183 경로 감사 결과가 개선된 것으로 주장하지 않는다.

검증: protocol 4 계약/JSON Schema 동기화, 구버전 후진 거부, 기하 및 기존 주행 관련 Python 테스트 51개 통과. Unity 검증 결과는 구현 현황에 별도 기록한다.
