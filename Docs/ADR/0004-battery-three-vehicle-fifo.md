# ADR 0004: 차량 3대의 가용 순서 FIFO와 합성 배터리

상태: 채택 · 2026-10-15 · 프로젝트 0.2.2.0

최신 사용자 요청은 배터리를 포함한 차량 3대 운행과 차량 FIFO다. ADR 0001~0003의 1대·배터리 제외 결정은 이 문서로 대체한다. 기존 OSM/Unity v2 경로와 30km/h 기준속도, 역 우회 복귀는 유지한다.

## 결정

- 요청은 접수 시각과 순번으로, 차량은 배차 가능한 상태로 들어온 순번으로 선택한다. 초기 대기열은 V01→V02→V03이며 복귀 또는 충전 완료 차량은 뒤에 넣는다. 같은 시각 충전 완료는 세션 생성 순서, 복귀는 운행 생성 순서로 처리하며 충전 완료를 먼저 반영한다. 용량·접근성·경로·에너지가 불충족인 후보는 건너뛰되 남은 차량의 순서를 바꾸지 않는다.
- 차량 3대 모두 승객 4명·휠체어 슬롯 1·화물 20kg의 합성 능력을 갖는다. 한 차량은 한 요청만 처리한다. 이 값은 실제 차량 모델 제원이 아니며 지도 Stop 접근성 미검증을 면제하지 않는다.
- 각 차량은 용량/초기 잔량 2,000Wh, 거리 소모 0.35Wh/m, 주행 보조전력 50W를 가정한다. 운송 구간만 승객 1명당 5%, 화물 1kg당 1% 거리 소모를 더한다. 픽업/복귀는 공차로 계산한다.
- 배정 전에 세 Dijkstra 경로의 예상 에너지 합과 정격 용량의 15% 예비량을 요구한다. 복귀 목적지는 정문의 가상 충전 거점과 같다. 잔량 부족이면 충전 대기 사유를, 완충해도 불가능하면 `BATTERY_CAPACITY_INSUFFICIENT`를 반환하고 배정하지 않는다. 후자는 현재 경로 없음 정책처럼 QUEUED를 유지하므로 운영자가 설정/요청을 수정해야 한다.
- 에너지는 각 경로 구간의 시간 진행 비율로 차감한다. 이는 동역학·고도·회생제동·센서 기반 실측이 아니다. 보조전력은 주행 중 전 구간에 적용한다. 거점 대기 차량은 전원을 끈 것으로 가정하여 대기 소모는 0이다.
- 거점의 이상적인 독립 충전 포트 3개를 가정한다. 순 저장 전력 1,000W로 완충까지 충전하며 충전 중 배차는 하지 않는다. 필요한 왕복 잔량이 부족하거나, 배정되지 않은 차량의 SOC가 30% 미만이면 충전을 시작한다. 복귀 시 가능한 요청 배정을 먼저 평가한다. 충전소 위치/설비/포트가 실제 존재한다는 주장은 아니다.
- 왕복/충전 완료 이벤트를 시간순으로 재생하여 큰 시간 점프와 작은 tick의 배정·에너지 결과를 일치시킨다. 배정 취소 후에도 기존 왕복 경로/예약과 보수적인 소모량을 유지한다.
- 설정 계약은 schema_version=2의 `vehicles`와 `battery`로 변경한다. 지도 위상은 같아 map_version=inha-osm-unity-v2를 유지한다. 설정·산출물 해시는 갱신하며 Unity 통신 schema_version=3은 바꾸지 않는다. 과거 1대/무배터리 검증은 명시적 factory 옵션으로 보존한다.

## 검증과 한계

`test_battery_fleet.py`는 3대 최초 배정, ID와 다른 가용 FIFO, 에너지 식·예비량 경계·적재 보정, 잔량 부족 충전·완충 불가·충전 완료 재진입, 취소, HTTP 및 18건의 큰/작은 시간 점프를 검사한다. 실행 방법과 전체 검증 결과는 `Docs/server_m0.md`, 실행 기록은 `artifacts/battery_fleet_validation.json`에 둔다.

현재는 Python 가상 시간 모델이다. 실제 배터리 계측·충전소/대기 전력 검증, 주행 중 예상 밖 방전·고장 복구, Unity 물리 주행과 다중 차량 경합/충돌 회피는 구현하지 않았다. 이 변경으로 M5 전체 완료나 실제 운송 안전을 주장하지 않는다.
