# ADR 0010 — 실제 도착 기반 요청 실행 분리

상태: 관측 기반 FIFO 실행기 연결, Unity V01 단일 승객 운송·복귀 검증 · 2026-10-25 · 미커밋

## 후속 실행기 구현

`PhysicalDispatcher`가 연결됐다. Unity 소유 차량이 등록된 세션에서 `/v1/demo/requests`로 접수한 요청은 외부 실행 대상으로 생성한다. 실제 차량 FIFO 후보에서 용량/접근성, 픽업·목적지·해당 차량의 명시적 home Stop 복귀 경로, 합성 배터리 예비량을 검사한다. home node와 일치하는 Stop이 없으면 임의 연결하지 않고 배차를 보류한다. 물리 배차 정책은 현재 FIFO이며 기존 가상 Greedy/Hungarian과 별개다.

픽업·하차 정차 후 각각 3초의 합성 서비스 시간을 적용한다. 해당 임무 ID의 ARRIVED·최신 접지/센서 유효·속도 0.05m/s 미만 관측에서만 진행하며, 같은 관측 tick 반복이나 오래된 관측으로는 대기 시간이 늘지 않는다. 요청 COMPLETED는 하차 서비스 후 기록하고 차량은 복귀 완료까지 예약된다. 픽업 전 취소는 픽업 지점 도착 후 복귀로 전환한다. 재접속 시 같은 요청의 현재 구간을 새 측정 위치에서 다시 계획한다.

합성 에너지는 실제 ego 이동 거리와 관측 간 벽시계 시간으로 기존 wh/m·보조 전력 모델에 따라 차감한다. 실측 배터리가 아니다. 사전 경로의 저속 시간 여유를 포함한 계획 에너지+15% 예비량을 검사하고, 실제 모델 잔량이 예비량에 닿으면 정지한다. 물리 차량의 자동 충전은 아직 미연결이다. 물리 소유 차량은 가상 충전/배차로 다시 가용 처리되지 않도록 분리한다.

검증: 합성 도착 관측으로 전체 상태 전환, 시간 경과만으로 완료되지 않음, 취소/재접속/용량/에너지 부족을 검사했다. 회귀 검사 155개 통과. 이 테스트는 실제 Unity 승객 운송 성공 증거가 아니며 별도 주행 검증이 필요하다. 아래 내용은 실행기 연결 전 결정 기록이다.

## 문제

### 후속 실제 검증 및 예약 보호

Unity V01의 도서관 픽업→하이테크 하차→정문 복귀를 실제 물리 주행으로 검증했다. 요청 COMPLETED 후에도 RETURNING 예약을 유지하고 정문 ARRIVED에서 READY/예약 해제를 확인했다. 총 이동 1,915.93m, 최고 40.63km/h이며 증거는 `artifacts/high_speed_drive/passenger-status.json`과 `physical-passenger-library-hitech.csv`다. 앞의 합성 테스트와 구분한다. protocol 4 제어 응답에 `transport_phase`를 추가해 운송·복귀 중 직접 목적지 지정 버튼과 호출을 차단한다. 관측/POST 사이에 예약이 잡히는 경우 서버 409 응답을 받아도 기존 운송을 영구 제동하지 않는다. 관련 Python 28개 검사 및 Unity MCP 컴파일 검사를 통과했다. Unity 임시 객체에 내부 예약 상태를 주입하는 검사는 MCP의 System.Reflection 사용 제한으로 실행하지 못했다. 실제 UI 예약 차단과 HTTP 응답 경합의 Unity 통합 검증은 남아 있다. 전체 거점과 자동 충전은 미검증/미연결이다.

기존 `MobilityService`는 요청 접수 시 가상 배차를 수행하고 경로 예상 시간이 지나면 운송을 완료한다. Unity Physics 차량은 별도로 목적지에 이동하므로 이 시간 재생을 실제 승객 운송 상태로 사용할 수 없다.

## 결정

- `create_request(..., external_execution=True)`로 접수한 요청 ID를 별도 실행 대상으로 보존한다. 기본값은 false여서 기존 HTTP/가상 시연 동작은 유지된다. 외부 실행 요청도 기존 Landmark/Stop/접근성 입력 검증을 통과해야 한다.
- 외부 실행 요청은 FIFO·Greedy·Hungarian 가상 배차 후보, 가상 충전 중단 시점 계산, 가상 차량 희소성 비용에서 제외한다. 대기 사유는 `WAITING_EXTERNAL_EXECUTOR`로 구분한다. 가상 시간이 지나도 이 요청의 운송은 완료되지 않는다.
- `UnityDriveSession.preview_mission`으로 실제 차량의 현재 pose 또는 계획상 후속 pose에서 차로/회차 경로를 미리 검사한다. 임시 계획 차량만 수정하고 실제 ego·임무·소유권·세션 시계는 바꾸지 않는다. 실패 시에도 원래 차량 참조를 복원한다.
- 실제 배차 실행기는 픽업·운송·복귀의 경로/용량/합성 배터리 여유를 먼저 검사하고, 이후 관측된 정차 도착으로 상태를 전환해야 한다. 지연·연결 중단·접지 문제를 시간 경과만으로 완료 처리하지 않는다.

## 실행기 연결 전 범위(과거 결정 기록)

실행기, 요청 UI의 실제 운행 연결, 승하차 대기, 실제 도착 완료 처리와 복귀는 아직 연결하지 않았다. 이 ADR의 서비스 경계만으로 정상 물리 배차가 구현됐다는 뜻이 아니다. 기존 목적지 직접 지정과 protocol 4 회차는 별도 구현이다.

검증은 `test_external_execution.py`의 세 배차 정책별 가상 완료 방지, 기존 가상 요청 배차 유지, 후속 회차 미리보기의 실차/시계 보존 및 실패 복원 검사로 수행한다.
