# ADR 0013: PC 연속 LiDAR와 물리 운행 protocol 5

- 날짜: 2026-10-28
- 상태: 시험 적용 / 0.5.3.0

## 배경

기존 PC 물리 protocol 4는 차체와 후륜 축을 관측하나 기본 고속 프로필에서는
장애물 감지를 비활성화했다. 팀 LiDAR는 독립 시연 씬의 다중 채널 관측과
시각화로 존재했다. 사용자 요청에 따라 실제 PC 운행에 센서를 연결한다.

## 결정

기존 제어 WebSocket 경로를 유지하고 PC 클라이언트를 protocol 5로 전환한다.
프로젝트/지도/독립 정지 gateway 버전과 혼용하지 않는다. protocol 1~4는 유지한다.

5는 `lidar`에 동일 tick, ray_count, max_range_m, valid와 전체 hit를 요구하고,
기존 `rays`는 빈 배열, obstacle_detection_enabled는 true다. hit는 자기 차체
기준 평면의 lateral_m/forward_m와 Raycast 의미 분류만 포함한다. 동적 Transform,
실제 속도/미래 궤적/객체 ID는 받지 않는다. 관측 불완전/버퍼 포화는 정지한다.

Simulation이 Presentation 인터페이스 factory를 등록하여 기존 PC 차량 3대에
센서를 붙인다. 10Hz에 맞춘 명시적 Capture로 스캔과 localization tick을 일치시킨다.
기본은 360×7/15m, 수직 -30~+15도이며 시험 튜닝이고 실측 성능이 아니다.

`campus_lidar`는 최대 18km/h와 도로 제한, TTC/정지거리, 차체/원래 경로 검사 및
관측 유효성 제약을 따른다. 회차보다 센서 정지를 먼저 수행하고 연속 5개 clear
scan 후 재출발한다. 알려지지 않은 동적 운동에는 넓은 여유를 두고 추적 완료로
표현하지 않는다. 기존 고속 프로필도 protocol 5에서는 센서 검사를 우회할 수 없다.

조우와 안전 제동은 기존 점군 셰이더 연출을 자동 활성화한다. PC 연출은 장면/UI를
숨기지 않는다. 표시 샘플링은 계산 관측을 줄이지 않는다. 트리거는 향후 Collider를
생성하는 입력이며 Python에 직접 장애물 위치를 알려주는 통로를 만들지 않는다.

RRT는 정지 후 정적/직선 차로 조건의 비실행 후보로 유지한다. 후보를 조향 명령으로
바꾸려면 차체/조향/시간 궤적/동적 충돌 검증이 추가로 필요하다. 현재는 정지와 대기,
관측 해소 후 재출발을 구현한 시험 통합이며 회피 운행 검증 완료가 아니다.

## 영향과 검증

PC와 Python을 함께 갱신해야 한다. 구형 서버가 protocol 5를 거부하면 차량은
watchdog로 제동한다. 모바일에는 센서 hit/debug를 전송하지 않는다. Player 셰이더
보존과 화질/FPS는 별도 빌드/렌더링 검증 대상이다. 시험/출처/한계와 원본 XML은
[8주차 통합 문서](../WEEK8_INTEGRATION.md)에 기록한다.
