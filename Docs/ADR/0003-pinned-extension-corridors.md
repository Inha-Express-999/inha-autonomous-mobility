# ADR 0003: 조사한 외곽 선분을 기본 가상 운행 지도에 반영

상태: 채택 · 2026-10-15 · 프로젝트 0.2.2.0 작업 트리 · map_version inha-osm-unity-v2

사용자는 하이테크·기숙사 1·2·3·인하대역 후보를 실제 FIFO/Dijkstra 가상 운행에 연결하도록 요청했다. 역은 Unity 자료에 있는 우회 복귀를 사용하고 차량 1대·30km/h·배터리 제외를 유지한다.

## 결정

- 전체 확장 OSM을 개방하지 않고 configs/osm_runtime.json의 extension_corridors에 93개 원본 선분 구간과 다섯 Stop 후보 way를 고정한다. 좌표를 직접 추가하는 자유 공간 연결은 허용하지 않는다.
- 기존 Unity core 조각을 동일한 확장 OSM 선분 위의 구간으로 정합한다. 같은 선분에서 실제로 겹치거나 맞닿는 범위만 병합하고 빈 구간은 유지한다. 다른 OSM node를 좌표 근접만으로 접속하지 않는다.
- 고정한 외곽 service/residential/secondary 구간만 추가한다. 모든 구간은 같은 OSM way의 Unity core/scoped/restored/일반 export 중심선과 대조하며 지원 자료가 없으면 실패한다. 이는 활성 메시·Collider·높이·통행성 승인이 아니다.
- 역의 미지원 지름길 way 1215102704는 graph에 넣지 않는다. 기본 복귀는 955217469→281621314→481241683이며 거리 약 407.16m다.
- OSM 방향·명시적 제한 및 낮은 숫자형 제한속도 우선 적용을 유지한다. 새로운 모든 Stop은 step-free 미검증이며 실제 접근성 조건을 완화하지 않는다.
- 도로 자료 변경을 구분하기 위해 map_version을 v1→v2로 올린다. 프로젝트 버전과 통신 schema_version=3은 별개다. 기존 HTTP 요청 형식·서비스 타이머·FIFO를 재사용한다.

## 결과와 검증

v2는 59 way/187 node/402 방향 edge, 14개 Stop 후보 전부 정문 왕복 가능이다. 다섯 동시 요청의 FIFO·완료 후 복귀·재배차, 다섯 곳을 출발지로 쓰는 3구간 요청, 역 우회, 원본 선분 보존/중복 방지 및 HTTP 통합을 포함해 Python 테스트 75개와 Ruff/format check를 통과했다. python -m campus_sim.demo_fifo --extensions로 기다리지 않고 재현한다.

Unity 씬/공유 에셋은 변경하지 않았다. 실제 차량 주행·승하차·센서·통행/폭/경사·보행/횡단 연결·안전 검증은 여전히 별도다. 현재 결과는 실제 형상을 쓰는 가상 시간 운행이며 실제 운송 지도 승인이나 M1/M2 전체 완료가 아니다.
