# ADR 0011: Unity에서 편집한 서비스 앵커를 Play 전에 검증·반영

2026-10-27 · 프로젝트 0.5.0.0 이후 미커밋 · Accepted

## 문제

기존 Unity 서버 지도 마커를 이동해도 Python의 정류장·허브·배차 경로는 바뀌지 않았다. 사용자는 Edit Mode에서 이동·저장한 위치가 Play 시 같은 서버와 웹 지도에 반영되는 흐름을 요청했다.

## 결정

- Python이 정적 서비스 앵커·지도·경로의 권위 상태를 유지한다. Unity의 Edit Mode 마커 X/Z를 편집 제안으로만 전달한다. 동적 차량/보행자 Transform이나 미래 궤적을 계획 입력으로 추가하지 않는다.
- 별도 `configs/service_locations.json` schema 1을 사용한다. 정류장/허브의 고정 ID와 Unity legacy X/Z를 저장하며 프로젝트 버전·지도 manifest schema와 구분한다. 없는 항목은 기존 자동 배치를 유지한다.
- Editor의 Play 진입을 보류하고 로컬 Python CLI가 후보를 생성·검증한다. 도로 중심선으로 투영하고 기존 통행 방향을 보존해 선분을 분할한다. 1cm 이내의 기존 분할점/도로 끝은 재사용해 퇴화한 미세 edge를 막는다. Unity는 아스팔트 Collider를 별도로 검사한다.
- 새 그래프·정류장·허브·우측 차로 프로파일·Unity export를 임시 디렉터리에 만든 뒤 발행한다. 실패하면 기존 지도·설정·export를 복구한다. 성공하면 Unity importer가 해당 지도에 맞춘 뒤 Play를 재개한다.
- 로컬 서버가 없으면 기존 PC 소유 방식 또는 Terrain Editor 전용 소유자가 서버를 시작한다. 같은 지도는 재사용하고, 다른 지도는 새 loopback 전용 `POST /v1/desktop/editor-map`에 expected/current hash를 보내 교체를 요청한다.
- Editor API는 Origin이 있는 요청과 loopback 이외 요청을 거부한다. 요청 이력·연결된 Physics 차량·시간 재생이 있으면 교체하지 않는다. 이전 서버에 API가 없거나 지도 일치에 실패하면 Play를 막고 원인을 표시한다. 다른 서버 프로세스를 강제 종료하지 않는다.
- 웹 상태에 geometry hash를 추가하고 변경 시 정적 지도도 다시 가져온다. 기존 소비자는 추가 필드를 무시할 수 있다.

## 범위·호환성

기존 위치와 통신 schema 번호는 유지한다. 새 Editor 편집·검증 절차만 추가하며 모바일/Player의 위치 편집은 지원하지 않는다. 서버 manifest는 변경된 builder와 추가 위치 검증 모듈의 hash를 포함해 재생성한다.

쉼터·차고 모델·차량 스폰은 독립된 표시/물리 배치다. 운행 앵커 이동으로 이를 순간 이동시키지 않는다. 실제 베이 연결·정차 방향·보행 접근 편집은 후속 범위다. 기존 unknown 접근성을 검증 완료로 바꾸지 않는다.

## 검증

전체 backend 307개 통과. 잘못된 좌표·미등록 ID·도로 밖 후보·기존 노드 재사용·반복 생성 안정성·실패 복구·서버 교체 거부/성공을 검사했다. Unity MCP에서 이동·저장 후 Play만으로 실제 서버의 정류장·허브와 hash/run ID 일치를 확인했고, 도로 밖 위치의 Play 차단도 확인했다. 시험 위치는 복구했다. 실제 운송·전체 주행·실단말 성능 결과로 해석하지 않는다.
