# ADR 0005: 차량 3대의 기본 출발·복귀 거점 분산

상태: 채택 · 2026-10-19 · 프로젝트 0.2.4.0

사용자는 정문에 집중했던 기본 배치를 후문·정문·운동장 옆 주차장 각 1대로 바꾸도록 요청했다. 기존 FIFO, 30km/h 가정, 배터리 예비량과 복귀·충전 모델을 유지한다.

## 결정

| 차량 | 거점 | 도로 연결 |
|---|---|---|
| V01 | 정문 | 기존 main_gate_road_candidate의 그래프 노드 |
| V02 | 후문 | 기존 rear_gate_road_candidate의 그래프 노드 |
| V03 | 운동장 옆 주차장 | 비룡주차장 OSM way568420971 안의 기존 node10058484941 |

설정 schema_version=3에 `hubs`와 `vehicles[].home_hub_id`를 도입한다. 구형 schema_version=2 지도 묶음은 재생성해야 한다. `home_landmark_id`와 manifest의 `home_stop_id`는 정문 기준 커버리지/조사 참조이며 차량 전체의 공통 복귀 지점이 아니다. map_version=inha-osm-unity-v2는 도로 위상이 그대로이므로 유지한다.

주차장은 `Docs/MapResearch/Iterations/HUB.md`의 사용자 확정 대운동장 서쪽 부지와 같다. `west-field-hub-validation.json` 및 `CampusVehicleHub.cs`의 주차장/허브 ID를 대조한다. 선택 노드는 OSM service way1098539016에 있고 원본 선분이 Unity core 중심선으로 대조되어 있다. Unity 허브 중심의 AEQD 변환점과 약 42.6m 떨어진 **기존 도로 노드**이며 실제 주차 베이나 허브 내부 진입로를 나타내지 않는다. 미검증 베이로 직선 연결하거나 도로/노드를 새로 만들지 않는다.

Map Builder는 주차장 polygon이 실제 OSM parking way인지, 선택 노드가 polygon 안의 기존 연결 도로인지, Unity 허브 ID와 일치하는지 검사한다. 각 거점에서 14개 Stop 후보까지 양방향 Dijkstra 가능성을 검사하고 불가능하면 생성을 실패시킨다. 거점별 노드와 차량 바인딩을 해시 검증 대상인 build_report/policy에 기록하며 loader에서도 대조한다. 원본 허브 기록과 생성 코드도 manifest 출처 해시에 포함한다.

차량은 자기 거점→pickup→dropoff→자기 거점으로 운행한다. 픽업/복귀 거리와 시간, 적재 구간 및 전체 왕복 에너지/15% 예비량은 차량별 실제 그래프 경로로 계산한다. 거점에 돌아오기 전에는 배정하거나 충전하지 않는다. FIFO 순서는 가용 대기열을 따르며 가장 가까운 차량을 고르는 정책으로 바꾸지 않는다.

각 거점에 독립 충전 1포트/순 저장 1,000W가 있다고 가정한다. 실제 시설 존재나 설치 완료가 아니다. 현재는 차량마다 전용 거점이므로 충전 자원 경합을 다루지 않는다. 즉시 가능한 요청 배정을 먼저 평가하며, 배정되지 않은 유휴 차량은 잔량 100% 미만이면 보충 충전한다. 완충 후 FIFO 뒤에 넣는다.

웹은 차량별 거점명·초기 좌표·복귀 경로·충전 위치와 로그를 서버에서 받아 표시한다. 원본 OSM 주차장 polygon과 운동장도 주변 형상으로 표시한다. 주차장 거점은 승객 Stop을 추가하는 것이 아니므로 승하차 후보는 14곳을 유지한다. 초기화와 서버 재시작도 같은 분산 배치를 복원한다.

## 검증과 한계

`test_home_hubs.py`는 기본 노드 분산, 42개 거점-Stop 왕복, 차량별 경로/에너지/충전/완충 후 FIFO, 웹 초기화, 가까운 차량보다 FIFO 우선, 잘못된 주차장·Unity/허브 바인딩 거부를 검사한다. 실행 증거는 `artifacts/distributed_hubs_validation.json`에 기록한다.

도로 59 way/187 node/402 방향 edge는 그대로다. 실제 통행·폭·주차 베이·출입구·보행 접근성·충전 설비는 승인되지 않았다. 이 변경은 정적 거점 운용이며 수요 재배치, 다중 차량 충돌 회피, Unity Physics/센서 운행 구현이 아니다. 과거 단일 정문 배치 기록의 운행/충전 횟수·시간은 현재 기본값에 적용하지 않는다.
