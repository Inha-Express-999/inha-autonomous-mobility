# ADR 0001: FIFO와 Dijkstra를 사용하는 합성 왕복 시간 실행

상태: 채택 · 2026-10-15 · 프로젝트 0.2.2.0

사용자는 FIFO 배차, 가상 정밀지도의 Dijkstra 경로, 복귀 시간 경과 후 재배차를 요청했다. 기본 차량은 한 대이며 배터리는 제외한다.

## 결정

- 기존 HTTP 요청/조회/취소 API를 유지하고 순수 FIFO와 Dijkstra를 별도 모듈로 추가한다.
- 합성 방향 그래프에서 출발 거점→pickup→dropoff→출발 거점의 세 경로를 각각 탐색한다. 복귀 불가 요청은 대기시킨다.
- 목적지 도착 시 요청은 완료되지만 차량은 복귀 시각까지 점유한다. 누적 비용의 합성 시간으로만 판단하며 Unity 위치·물리·센서 완료를 주장하지 않는다.
- 기본 1대/6거점으로 실행한다. 복귀 이벤트를 시간순으로 처리하고 서버 tick이 자동으로 진행한다. 재현 테스트는 주입 clock과 명시적 step을 사용한다.
- 승하차 지연은 현재 0초 가정이다. 기존 고정 ETA를 경로 기반 합성 목적지 ETA로 바꾼다.
- 배정 후 픽업 전 취소는 요청을 취소하되 원래 왕복 예약을 유지한다. 중간 위치 회차와 탑승 후 안전 취소는 후속 작업이다.
- Unity 화면 DTO/schema_version=3은 보존하고 별도 로컬 debug API로 시간·경로·가용 상태를 제공한다.

## 영향과 후속 작업

합성 시간 완료와 실제 운송 완료를 명확히 구분한다. 후속 Unity 통합에서는 타이머만으로 승하차·완료를 승인하지 않고 도착/정지/서비스 시간을 검사해야 한다. 인증된 principal·command_id 충돌 검사는 기존 API의 미완료 항목이다. 실제 지도 검증, A* 비교, 차량 제원·제어·센서 연결 이후 3대로 확장한다. 배터리는 명시적 후속 범위다.
