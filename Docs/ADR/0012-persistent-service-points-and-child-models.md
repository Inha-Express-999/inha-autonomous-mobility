# ADR 0012: ID 기반 포인트 갱신과 자식 표시 모델 보존

2026-10-27 · 프로젝트 0.5.0.0 이후 미커밋 · Accepted

## 결정

사용자는 같은 ID의 포인트를 유지하고, 정류장·차고 3D 모델을 각 포인트의 자식으로 연결하며 Unity에서 편집한 위치가 Play 시 서버 지도에 반영되도록 요청했다.

- 지도 importer는 `(MarkerKind, serverId)`로 기존 포인트를 찾는다. 같은 ID의 GameObject와 컴포넌트를 유지하고 서버 노드 바인딩·위치·이름·차량 연결 정보만 갱신한다. 새 ID만 생성한다.
- 정류장 쉼터 14개와 차고 3개를 기존 월드 위치·회전·크기를 유지하며 해당 포인트의 직접 자식으로 이전한다. `ServicePointVisual`은 소유 포인트 종류·ID를 저장하며 런타임 업데이트를 추가하지 않는다.
- 포인트 이동 시 자식 모델이 함께 이동한다. 모델만 조정할 때는 로컬 Transform을 편집한다. 지도 갱신은 모델의 저장 ID·로컬 위치·회전·크기를 보존한다. 위치가 바뀌지 않은 포인트의 표시 높이도 불필요하게 다시 투영하지 않는다.
- 지도에서 사라진 ID 중 자식이 있는 포인트는 비활성 보존 루트로 옮겨 모델을 잃지 않게 한다. 같은 ID가 돌아오면 보존된 포인트를 재사용한다. 자식이 없는 제거 대상만 정리한다.
- 기존 세 가지 합친 디버그 마커 메시만 갱신한다. 사용자 표시 모델을 삭제·재생성하지 않는다. 쉼터/차고 빌더도 이미 연결된 모델을 유지하고 누락된 모델을 추가하는 방식으로 바꾼다.
- 차량과 Physics 객체는 포인트의 자식으로 만들지 않는다. 모델은 Collider/Rigidbody가 없는 표시 계층이며 기존 이동·충돌 판단을 대체하지 않는다.

## 서버와의 경계

ADR 0011의 Play 전 Python 검증·지도 생성·서버 동기화를 유지한다. 부모 포인트의 X/Z만 위치 편집 입력이다. 자식 모델의 로컬 배치는 서버의 정차 위치를 바꾸지 않는다. Y·회전·크기는 표시 편집이며 지도 좌표·정차 방향·차량 스폰 또는 접근성 승인으로 해석하지 않는다.

통신 schema와 프로젝트 버전은 변경하지 않았으며 커밋 시 별도 버전 증가·동기화 규칙을 적용한다.

## 검증

Unity MCP에서 초기 17개 모델의 월드 위치 보존을 확인했다(최대 오차 약 0.0000004m). 동일 지도 재가져오기 두 번과 실제 지도 hash가 바뀌는 Play 실행 전후로 포인트·모델 GlobalObjectId 및 로컬 배치가 유지됐다. 자식의 이동 추종, 모델만 이동할 때 부모 위치 불변, 차량 위치 불변도 확인했다. 실제 서버와 Unity의 지도 hash·run ID가 일치했다. 시험 위치는 복구하고 씬을 저장했다.

Renderer·재질·메시·Static Batching 플래그를 유지했다. 성능 향상이나 PC/모바일 FPS를 측정한 결과는 아니다. 실제 운송·전체 주행·모바일 실행 검증은 별도다. 자동 테스트 실행 결과와 미완료 항목은 `artifacts/point_hierarchy/`의 결과 기록을 따른다.
