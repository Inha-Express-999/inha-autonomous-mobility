# 클라이언트 명세 적용 및 검증 계획

프로젝트 기준 **0.1.2.0** · 2026-09-22 · 상태: 클라이언트 씬·어셈블리·빌드 프로필 골격 구현, UI/서버 구현 전.

[REQUIREMENTS.md](REQUIREMENTS.md)는 사용자가 제공한 원문 34절을 그대로 보존한다. 모든 절을 구현 범위에 포함하며, 화면 예시의 ID·ETA·밀도·수치·Stop 명칭은 합성 예시다. 원문이 이미 구현되었다는 뜻이 아니다.

## 제작 순서와 역할

1. [지도 계획](../MapResearch/PLAN.md)의 최신 재검수 항목을 해결한다. 허브 접지·위치, 자연스러운 도로 경사·필수 거점 연결, 불필요한 교외 도로 제거, 운동장 선, 풀, 주요 건물 외형·재질, 인경호 보도를 확인한다. 이 기준이 충족되기 전 UI 단계 완료를 선언하지 않는다.
2. 공통 `CampusWorld`와 PC 가로 `PC_Operator`, 모바일 세로 `Mobile_Passenger`를 Additive 구성한다. 앱당 네트워크 세션·상태 저장소·EventSystem은 하나만 둔다. UI/카메라/품질과 역할별 표시를 분리한다.
3. UI 목업과 검색·선택·필터·화면 전환·카메라·품질 설정 등 일부 기능을 구현한다. 목업에는 **데모 데이터** 상태를 표시하고 실서버 연결 표시와 혼동하지 않는다. fixture 제공자를 추후 서버 제공자로 교체할 수 있게 분리한다. 목업의 상태 전이는 배차 알고리즘이나 가짜 실운행으로 구현하지 않는다.
4. Python authoritative 서버를 구현한다. A*/RRT·배차·보행자·혼잡·안전·Stop 결정·요청 상태·ETA는 서버에 둔다. 기존 M0~M6 검증을 생략하지 않는다.
5. 동일 run/map/tick의 PC·모바일을 연결해 §34 동시 시연 흐름과 단절·실패·취소를 검증한다. 실제 기기에서 UI ≥30 FPS를 측정하고 기준 장비와 품질을 기록한다.

## 공통 표현과 계약 적용 결정

- 디자인: Apple과 같은 간결한 앱 스타일을 지향한다. 절제된 중립색, 충분한 여백, 일관된 글자 크기·아이콘, 명확한 선택/비활성 상태, 최소한의 강조색을 사용한다. 장식보다 지도·호출 상태를 우선한다. 로고·서체 등 타사 자산을 무단 복제하지 않는다.
- PC는 가로, 모바일은 세로 고정이 기본이다. 모바일 Safe Area·키보드·검색 목록·Bottom Sheet가 주요 조작을 가리지 않도록 검사한다. 터치 대상은 44 UI 단위 이상을 설계 목표로 삼고 실기기에서 확인한다.
- 연결됨/재연결 중/연결 끊김은 아이콘과 문자로 표시한다. 마지막 유효 서버 상태 수신 후 **1초 이상**이면 보간과 ETA 갱신을 멈추고 M12/P08에 오래된 상태임을 표시한다. 시간 판정은 단조 증가 실시간 기준이며 배속·일시정지와 분리한다.
- 재접속은 역할·요청 소유권을 확인한 완전한 snapshot/seq로 복구한다. 단절 자체가 요청 자동 취소나 전체 시뮬레이션 정지를 의미하지 않는다. 연결 확인 전 조작 성공을 표시하지 않는다.
- 모바일 입력은 landmark_id·party_size·service_needs·선택적 마감이다. 사용자가 Stop을 직접 확정하지 않는다. `wheelchair_slots > 0`이면 `requires_step_free=true`를 요구하고 서버에서도 검증한다.
- 원문의 `WAITING` 등 화면 예시는 도메인 enum을 추가하지 않는다. 배차 대기는 `QUEUED` 등 서버 상태에서 UI 문구로 매핑한다. `DROPOFF_SERVICE`는 하차 진행 안내이며 `COMPLETED` 전에는 완료 처리하지 않는다. 랜드마크 최종 보행 도착은 별도 상태다.
- 원문의 ‘현재 위치’는 검증된 랜드마크 선택/서버가 승인한 대응이 있을 때만 사용한다. 임의 GPS→Stop 스냅이나 미검증 승차 위치 생성은 하지 않는다.
- 확인 화면의 예상 소요·ETA는 서버 응답으로만 표시한다. 서버 미연결 목업은 예시임을 명시하고 실제 예상치로 제시하지 않는다. 사유 누락 시 임의로 안전/혼잡 원인을 추정하지 않는다.
- 취소는 서버 command와 ack/reject 결과에 따른다. 모바일은 자신의 요청만 취소하며, 탑승 후에는 기존 안전 거점 정차·운영자 처리 정책을 따른다. UI 버튼으로 차량 운행을 직접 시작하지 않는다.
- 모바일에는 자신의 요청·차량·Stop·경로·서비스 상태만 전달한다. 다른 승객 위치, 전체 요청/군중, 관제 debug는 단순 숨김만 하지 말고 서버의 역할별 구독에서 제외한다. 차량/보행자 렌더 생략이 서버 시뮬레이션 개체 삭제로 이어지지 않는다.
- PC 시계/배속/이벤트는 서버 명령이다. 시간 Jump는 새 run 또는 정의된 상태로 시작하며 기존 WorldState의 시각만 바꾸지 않는다. 배속 ×0.5/1/2/5/10은 고정 dt를 바꾸지 않는다.
- 네 자리 프로젝트 버전은 PC 상단, 모바일 정보/연결 화면, 접속 로그에 표시한다. map_version·schema_version·프로젝트 버전은 독립적으로 관리한다. OSM 출처를 두 지도 화면에서 확인할 수 있어야 한다.

## PC 구현·인수 표

모든 항목의 현재 상태는 **미구현**이다. P02~P08은 P01 내부 패널/창이며 별도 역할 Scene을 늘리지 않는다.

| ID | 구성과 필수 기능 | 검증 증거 |
|---|---|---|
| P01 | 상단 Control Bar, 좌측 Status, 중앙 Campus 3D, 우측 Inspector, 하단 Timeline. 시간·배속·run/map/project 버전·연결, Play/Pause/Stop/Reset, 지정 시간 Jump. 전체 차량/요청 집계·필터·목록, 승객/화물 입력 | 가로 화면 캡처, 서버 명령 ack/reject, 집계와 snapshot 대조 |
| P02 | 차량 ID·Mission/Motion·배터리·속도·요청·route·판단 이유. 클릭 Focus, 더블클릭 Follow, 차량 Floating UI | 목록/3D 선택이 같은 ID를 가리키고 상태·단위·사유 일치 |
| P03 | 요청 유형·출발/목적 Landmark·서버 결정 Stop·대기시간·마감·차량·ETA·취소 결과 | Stop 변경 이유 및 불가/거부를 서버 이벤트와 대조 |
| P04 | Zone polygon·Observed/EMA/Forecast person/m²·NORMAL/CAUTION/AVOID/CLOSED·threshold·정책 | 단위·현재/예상 구분, 색상 이외 상태 표기 |
| P05 | 보행자 횡단·공사·차량 고장·군중 급증·도로 폐쇄 Scenario Event | 승인 tick과 결과 로그, Unity에서 상태 직접 수정 없음 |
| P06 | 정책·알고리즘 결과 분석과 지표 | 서버 실행/실험 자료와 지표 일치, 미측정 값 구분 |
| P07 | Simulation 설정·품질·카메라/Overlay 설정 | 입력 검증·권한·서버 반영 여부, 품질 변경 시 상태 보존 |
| P08 | 연결·시스템 상태·버전·오류·재접속 | 1초 단절과 snapshot 복구 검사 |

P01 공통 Overlay는 Crowd Heatmap, Vehicle Routes, Global A*, Local RRT, Stop, Landmark, Zone, Vehicle ID, Pedestrian을 각각 켜고 끈다. 이전 경로를 남길 경우 변경 tick·사유·표시 기간을 구분한다. Timeline 필터는 ALL/VEHICLE/REQUEST/CROWD/SAFETY/ROUTE/ERROR다. 카메라는 WASD 이동, 우클릭 회전, 휠 줌, 중간 버튼 Pan과 Free/Top/Vehicle Follow/Landmark Focus를 제공한다. UI 입력 중 카메라 조작이 겹치지 않아야 한다.

모든 항목의 현재 상태는 **미구현**이다. 세로 화면에서 검색/목록으로도 모든 필수 조작이 가능해야 한다.

| ID | 화면과 필수 기능 | 검증 증거 |
|---|---|---|
| M01 | Splash/Connect, 연결 결과·프로젝트 버전 | 연결 성공/실패/재시도별 화면 |
| M02 | Main Map, 쿼터뷰·출발/목적 Bottom Sheet·드래그·핀치·Landmark 선택·내 차량 Follow | 세로 Safe Area, 제한된 회전/고도, 지도와 목록 선택 일치 |
| M03 | Landmark Search, 최근/전체·별칭 검색, 필수 11개 목록 | 미검증/불가 시설을 이용 가능으로 오인시키지 않음 |

| M05 | Request Confirm: 출발/목적·인원·지원조건·서버 예상 소요·호출 | 같은 출발/목적 등 오류, 중복 호출 방지와 서버 거부 표시 |
| M06 | Dispatch Waiting, 대기시간·상태·취소 | QUEUED/대기·취소 ack/reject와 화면 일치 |
| M07 | Vehicle Assigned, 차량 ID·ETA·서버 Stop 결정/선택 이유·변경 안내 | 내 차량만 강조, 다른 요청 정보 미노출 |
| M08 | Vehicle Approaching, ETA·승차 위치·접근 경로 | TO_PICKUP 및 서버의 변경 사유 반영 |
| M09 | Pickup, 차량 도착·출입구·탑승 안내 | 서버 PICKUP_SERVICE 전환, 직접 출발 버튼 없음 |
| M10 | In Transit, 내 차량·현재 경로·목적지·선택 Stop·ETA | TO_DROPOFF, 혼잡 우회·보행자 양보·재탐색 안내 |
| M11 | Dropoff/Complete, 도착·출입구·이용 시간·확인/재호출 | DROPOFF_SERVICE와 COMPLETED 구분, 보행 최종 도착 별도 |
| M12 | Connection Lost, 재연결·오래된 상태 표시 | 보간/ETA 중단, 요청 유지 및 전체 snapshot 복구 |
| M13 | Request Failed, REJECTED/EXPIRED/FAILED 사유와 가능한 후속 선택 | 원인 추측 없음, 접근성 제약 완화·가짜 성공 없음 |

이동지원→출발→목적→확인→호출→대기→배정/접근→탑승→이동→하차/완료 흐름을 연결한다. 모바일에는 전체 군중/차량 상세/요청/타 승객 위치/Heatmap/RRT 샘플/A* debug/충돌 debug/배차 점수/내부 로그를 표시하지 않는다. 승객 안내는 서버의 상태+사유 조합을 사람이 이해하기 쉬운 문장으로 매핑한다.

## 성능과 완료 증거

- 모바일 저LOD 건물·단순 재질·원거리 그림자 제한, 내 차량 정상 LOD, 기타 차량 선별 표시, 보행자 기본 비표시를 품질별로 검증한다. PC 고품질 표현과 데이터 모델은 공유한다.
- 기기·해상도·Quality Level·평균 FPS·p95 프레임 시간·메모리·Draw Call/Batch·표시 Landmark/차량 수를 기록한다. 목표 30 FPS와 실제 측정값은 구분한다.
- 원문 §31 기능 비교표 전체를 역할 권한 검사에 반영한다. PC의 운영자 권한과 모바일 요청 소유권은 서버에서 확인한다.
- 원문 §34의 호출→배차→Stop 선택→10:30 혼잡 우회→보행자 양보→재출발→도착을 PC·모바일 화면 및 동일 run/map/tick 로그로 대조한다.
- 별도 실패 시나리오: 1초 갱신 중단, 재연결, 요청 중복 전송, 권한 없는 취소, 미검증 Stop, 접근 가능한 대체 거점 부재, 시간 Jump, 서버 오류. UI 목업 성공만으로 이 검증을 통과한 것으로 표시하지 않는다.
