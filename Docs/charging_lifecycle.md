# 합성 충전 슬롯 상태 관리

2026-09-26 · v0.4.2.0

## 구현 및 검증 범위

명시적 합성 충전소 설정으로 정차 충전, FIFO 슬롯 예약, 충전 완료 및 위치 확인 후 슬롯 해제를 처리한다. 차량 위치를 변경하거나 배터리를 즉시 복원하지 않는다. 서버 기본 설정에서는 비활성이다.

- 한 충전소에서 한 차량만 전력을 받는다. 동일 요청을 반복해도 큐 진입 시각을 보존한다.
- 도착 반경 내 정차, 유효한 에너지 모델·지도·차량 세션과 신선한 위치가 필요하다. 첫 확인 tick은 충전량을 증가시키지 않는다.
- 전력×효율×유효 경과 시간으로 에너지를 적립하고, 서비스의 보조전력 소모는 계속 차감한다. 설정 목표 잔량까지만 적립한다.
- stale 위치, 세션 변경, 지도 불일치는 슬롯을 유지하며 적립을 중단한다. 같은 문맥의 freshness 복구는 새 확인 시점부터 재개한다. 세션 변경은 자동 복구하지 않는다.
- 완료 여부는 일시 중단 상태와 별도로 유지한다. 완료 차량은 새 운송을 받을 수 있지만 슬롯은 이탈 반경 밖의 연속 확인 기간을 충족한 뒤 해제한다. 긴 갱신 공백은 적립 및 이탈 대기 시간을 초기화한다.
- 슬롯을 점유했거나 위치가 불명인 소유자의 취소로 슬롯을 비우지 않는다. 미배정 대기 취소는 가능하다.

## 실행

저장소 루트에서 기존 Python 환경으로 다음 옵션을 사용한다.

```text
python -m campus_sim.cli serve --energy-config configs/energy.synthetic.json --charging-config configs/charging.synthetic.json
```

`/health`의 `charging_status=SYNTHETIC_PARKED_ONLY`로 제한된 모드를 표시한다. 설정은 기존 합성 6-stop 지도 n1/n6을 사용하며 실제 캠퍼스 충전시설의 존재·위치·출력 근거가 아니다. 기본 에너지 초기 잔량 600Wh는 자동 시작 기준 20%보다 높으므로 시작 직후 충전하지 않는다. 잔량이 기준 이하이고 이미 dock에 정차한 차량만 자동 대기열에 들어간다.

## 검증

충전 전용 테스트 11개 및 전체 Python/MapData 467개 통과, Ruff 통과. 전용 테스트는 시간·중복 tick·긴 공백·역행 시간, FIFO/독점 전력, 완료 유지, context 복구, 실제 ego 메시지의 stale/resume, 세션 교체, 연속 이탈 확인, 설정 검증을 포함한다. production 서비스 advance를 사용해 15Wh 부족 차량이 충전한 뒤 대기 승객 요청을 수행·완료하고 슬롯을 해제하는 흐름도 검사한다.

## 남은 범위

충전소 자동 경로·이동, 대기 장소/통로 예약 결합, 물리적인 dock 크기·차체 배타성, 여러 위치 표본 사이 연속 점유, 충전소 고장 및 운영자 복구, PC/모바일 충전 상세 안내, Unity Physics/Player 검증은 미완료다. 현재 큐는 전력 슬롯의 논리적 배타성만 보장하며 차량 간 물리 충돌 회피를 대신하지 않는다. 에너지 모델과 모든 충전 제원은 합성 가정이다. M5 및 전체 MVP 완료를 의미하지 않는다.
