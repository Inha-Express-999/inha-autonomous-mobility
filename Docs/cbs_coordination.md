# CBS 오프라인 작업 체크포인트

2026-09-26 · project version 0.4.1.0

자체 시간 확장 A*와 두 차량 제약 분기를 사용하는 유한 horizon CBS, 고정 우선순위 예약 비교를 구현했다. 목표는 도착 tick 합 최소화다. 노드 점유, 동일/역방향 edge의 전체 시간 구간, 명시적 공유 자원 및 clearance tick을 검사한다. 목적지 점유는 horizon 끝까지 유지한다. 합성 지도와 정적 통행/차량/접근성 제약만 허용한다.

실행: `campus-sim coordination-compare --scenario configs/coordination_benchmark.json --repetitions 5`

작은 그래프에서는 독립 전수 탐색의 최적 비용과 비교하고, 경로 불가·영구 목적지 점유·다중 tick·공유 자원·탐색 한도를 테스트했다. 전체 Python/MapData 374개가 통과했다.

세 차량 통로 fixture의 두 우선순위 사례를 각각 5회 실행했다. 우선순위 방식은 각 5/5 성공했으나 CBS는 각 5/5 CT 500개 한도를 초과했다. 짧은 horizon 사례는 양쪽 모두 성공하지 못했다. 실패 결과에는 실행 가능한 부분 계획을 반환하지 않는다. 결과와 입력/source hash는 `artifacts/validation/2026-09-26-cbs/`에 있다.

이는 오프라인 양자화 비교 기반이다. edge 비용을 tick 시간으로 올림하고 수기 자원 overlay를 사용한다. 연속 footprint, 센서 지연, 실제 물리 충돌, live lease/교착 복구와 제어 재계획을 검증하지 않는다. 모든 결과는 executable=false이며 live ResourceReservations 또는 actuator에 연결하지 않는다. CBS 성능 개선 또는 M5 완료를 주장하지 않는다.


## v0.4.0.0 이후 작업본: disjoint CBS

`cbs-disjoint`를 추가했다. 충돌 토큰 하나에 대해 선택 차량이 그 토큰을 사용하지 않는 분기와 반드시 사용하는 분기를 만든다. 필수 점유 분기에서는 나머지 모든 차량에 해당 토큰을 금지한다. 시간 확장 A*는 필수 점유의 충족 이력까지 상태에 포함하고, 목적지 주차/이전 이동의 clearance 점유도 반영한다. 분기 아이디어의 출처는 [Li et al., ICAPS 2019](https://ojs.aaai.org/index.php/ICAPS/article/view/3487)이며, 구현은 프로젝트의 다중 tick·공유 자원 모델에 맞춘 자체 구현이다.

차량별 동일 제약의 경로는 한 solve 안에서 최대 4,096개 LRU 항목으로 재사용한다. 다른 문제/호출 사이에 재사용하지 않는다. 기존 `cbs` 기본 선택과 고정 우선순위 방식도 유지한다. 비교 CLI는 세 방식을 모두 실행한다.

동일한 합성 통로, horizon 30, 2초 tick, 1 tick clearance에서 각 5회 실행했다. 먼저 CT 500 한도에서는 두 CBS 방식 모두 실패했다. 비교 설정의 CT 한도를 두 방식 모두 2,000으로 변경하고 재실행한 결과는 다음과 같다. LL 한도는 계속 50,000이다.

| 방식 / 사례 | 성공 | 총 도착 시간 | 완료까지 시간 | 정지 대기 합 | 계산 p50 |
|---|---:|---:|---:|---:|---:|
| 우선순위 / 기본 | 5/5 | 104초 | 54초 | 40초 | 3.24ms |
| 우선순위 / 역순 | 5/5 | 114초 | 56초 | 50초 | 3.75ms |
| 기존 CBS / 두 사례 각각 | 0/5 | 미산출 | 미산출 | 미산출 | 약 2,255ms |
| disjoint CBS / 두 사례 각각 | 5/5 | 94초 | 48초 | 42초 | 약 1,077–1,090ms |

새 방식은 각 실행에서 CT 666개를 확장했다. 총 도착 시간과 makespan은 개선됐으나 기본 우선순위 대비 정지 대기 합은 2초 증가했다. 목적 함수는 정지 대기 합이 아닌 총 도착 시간이다. 실패한 기존 CBS와의 최적 비용 비교는 할 수 없다. 세 차량 계획 충돌 토큰은 성공한 결과에서 0개이며 실제 Physics 충돌은 이번 오프라인 실험에서 측정하지 않았다.

검증: 작은 4-node 그래프의 160개 시작/목적지 조합을 독립 전수 탐색과 비교하고, 공유 자원의 2/3-job 직렬 처리 하한, 다중 tick, 영구 목적지 자원, 필수 점유와 탐색 한도 실패를 검사한다. 증거는 `artifacts/validation/2026-09-26-cbs-disjoint/`에 있다. 시간 수치는 개발 PC의 5회 표본이며 일부 실행과 Python 회귀 검사가 겹쳤다. 전용 성능/부하 측정이 아니고 실시간 목표를 충족했다고 주장하지 않는다.

live 예약/제어 연결, 지연 후 재계획, 실제 안전 계층 우선 동작 비교가 남아 있어 T25/E4/M5 완료로 간주하지 않는다. 실제 지도/Stop 승인 등 전체 MVP 범위도 그대로 남는다.
